어디까지 만드나

P0만으로 저널은 선다. 나머지는 P0가 실제로 쓰인 뒤에 판단한다.

P0 — 이것만으로 선다

  • 오늘 저널제목이 YYYY-MM-DD 인 페이지. 열 때 만들고 안 쓰면 안 만든다.
  • Journals 피드날짜 내림차순으로 이어 붙인 한 장. 그 자리에서 편집한다.
  • ⌘⇧J어디서든 오늘로 가서 마지막 줄에 캐럿을 놓는다.
  • 날짜 토큰 클릭그날 저널로 간다. 없으면 만든다.
  • 사이드바 분리저널은 Journals 칸에, 나머지는 Pages 칸에.

P1 — 쓰다 보면 아쉬운 것

  • 참조 목록date: 결과에서 자기 줄을 빼고 출처를 붙인다.
  • 남은 To-do 이어받기버튼을 누를 때만 옮긴다.
  • 미니 달력쓴 날이 보이는 한 달짜리 이동 수단.
  • 날짜 범위 검색date:2026-08-01..2026-08-07. 지금 필터는 하루만 받는다.

비대상 — 저널이 이유가 되지 못한다

  • [[페이지]] 링크와 backlink저널은 날짜만으로 선다. 링크 해석기와 역참조 색인은 그 자체로 따로 설계할 일이다.
  • 템플릿, SCHEDULED / DEADLINE, 쿼리 문법Logseq에서도 저널을 쓰는 사람 대부분이 안 쓴다.
  • journals/ 전용 폴더폴더 규칙을 저널 때문에 갈라놓으면 동기화가 갈라진다.

이미 깔려 있는 것

P0에서 새로 만드는 코드는 화면 두 개와 단축키 하나 정도다. 아래는 그대로 쓸 자리다.

필요한 것이미 있는 자리손댈 부분
날짜 색인 notes_dates · mutations.rs의 derived_dates 없음. 제목·노트에 쓴 날짜가 이미 들어간다
날짜로 찾기 queries.rs의 date: 필터 참조 목록에서 자기 페이지 줄을 빼는 조건 하나
날짜 토큰 outlinePresentation.ts의 matchDate · OutlineTextField.tsx span을 button으로 바꾸고 클릭을 태그 경로에 붙인다
날짜 입력 outlineSlash.ts의 /today · localDateIso 없음. 저널 제목도 같은 함수로 만든다
피드 읽기 ForestRequest.rootIds — 이미 배열이다 저널 뿌리를 날짜순으로 골라 넘기는 조회 하나
페이지 만들기 · 열기 notesStore.createPage · openPage 제목을 날짜로 주고 같은 날 페이지가 있으면 그것을 연다

정하고 시작할 것

저널인지 무엇으로 아는가. 제목이 YYYY-MM-DD 면 저널로 본다면 스키마가 늘지 않고 vault 폴더 이름만 봐도 읽힌다. 대신 보통 페이지의 제목을 날짜로 바꾸면 그 페이지가 저널이 된다. Logseq도 그렇게 동작한다. 컬럼을 따로 두면 그 일은 막히지만 새 열과 새 규칙이 하나씩 는다.

제목 표기. 화면에는 2026-08-21 금요일로 그리고 저장은 2026-08-21 하나로 굳힌다. 표기를 설정으로 열면 파일 이름과 색인이 같이 흔들린다.

피드의 첫 화면. 앱을 켜면 Journals를 열지, 마지막에 보던 페이지로 돌아갈지. 저널을 매일 쓰는 사람에게는 앞이 맞고 그렇지 않으면 뒤가 맞다.
