# Yonalist iOS v1 — 기능 설계 시안

아직 계약이 아니라 논의용 시안이다. 화면 구성과 범위가 합의되면 항목표를 붙여
계약으로 승격한다.

## 1. 계약 초안

| 항목 | 내용 |
|---|---|
| 목표 | iPhone에서 오늘 저널을 열어 쓰고, 데스크톱과 iCloud로 같은 vault를 공유한다 |
| 타겟 | iPhone 15 Pro (393×852pt), iOS 17+ |
| 비대상 | GN 플러그인, GitHub 설정, PDF/Markdown 내보내기, Trash, 드래그 재배치, 분할 창, 첨부 편집(보기만), iPad 레이아웃 |
| 데이터 결정 | 스키마 변경 없음. 데스크톱과 같은 markdown SSOT + SQLite 캐시. vault는 앱의 iCloud 컨테이너 `Documents/`에 둔다 |
| 동기화 | 기존 `notes-sync` HLC 병합을 그대로 쓴다. iOS 쪽 새 코드는 "iCloud 파일을 내려받게 만드는" 층뿐이다 |

### 완료 조건 초안 (v1)

| # | 조건 |
|---|---|
| A1 | 첫 실행에서 iCloud 컨테이너에 vault를 만들거나, 이미 있으면 그대로 연다. Mac은 `~/Library/Mobile Documents/iCloud~<bundle>/Documents`를 vault로 지정해 같은 파일을 본다 |
| A2 | 앱을 열면 오늘 저널이 바로 나온다. 없으면 첫 글자가 들어올 때 만든다(데스크톱 A2와 같은 규칙) |
| A3 | 줄을 눌러 편집하고, 키보드 액세서리 바로 들여쓰기·내어쓰기·새 줄을 한다 |
| A4 | 불릿을 누르면 완료 상태가 데스크톱 ⌘↩과 같은 3단계로 돈다 |
| A5 | Journals 탭은 날짜 내림차순 피드다. 맨 위 하루만 편집, 지난 날은 읽기 전용(데스크톱 A5와 동일) |
| A6 | Carry over가 앞선 7일의 안 끝난 To-do를 오늘로 옮기고, 옮길 것이 없으면 버튼이 없다 |
| A7 | Pages 탭은 저널이 아닌 페이지 목록이고, 페이지를 열면 아웃라인이 보이고 편집된다 |
| A8 | 검색 탭에서 본문·제목·`date:` 필터가 데스크톱과 같은 결과를 낸다 |
| A9 | 다른 기기가 바꾼 파일이 iCloud로 오면 앱이 앞에 있는 동안 화면에 반영된다. 충돌은 HLC 병합이 데스크톱과 같은 규칙으로 푼다 |
| A10 | 아직 내려받지 못한(dataless) 파일 때문에 병합이 잘못된 판정을 내리지 않는다 — 내려받기 전에는 그 파일을 건드리지 않는다 |

## 2. 아키텍처 결정과 버린 것

**Tauri 2 iOS로 간다.** 데스크톱이 이미 Tauri라 `notes-core`·`notes-sqlite`·
`notes-sync` Rust 크레이트가 그대로 올라간다. 편집기는 WKWebView 위에서 이미
검증됐다 — macOS Tauri도 WKWebView라서 contenteditable·클립보드·selection의
함정을 이 저장소가 이미 밟고 고쳐 놨다. 새로 쓰는 것은 모바일 셸 UI와 iCloud
브리지 플러그인뿐이다. — 버린 것: SwiftUI + Rust FFI 재작성. 편집기를
네이티브로 다시 만드는 값이 "빠르게"라는 목표와 정면으로 충돌한다.

**vault는 앱 전용 iCloud 컨테이너에 둔다.** iOS 앱은 임의의 iCloud Drive 경로를
계속 읽을 수 없고, 자기 ubiquity 컨테이너만 항상 접근된다. 이 컨테이너는 Mac의
iCloud Drive에도 폴더로 나타나므로 데스크톱은 그 경로를 vault로 지정하면 된다.
— 버린 것: 문서 피커로 기존 vault 폴더를 고르게 하기. security-scoped bookmark
가 만료·회수되는 경우를 다뤄야 하고, 백그라운드 동기화 접근이 불안정하다.

**iCloud 내려받기는 iOS 전용 층이 필요하다.** macOS에서는 dataless 파일을 읽으면
곧 내려받기다(2026-08-20 iCloud 설계 문서). iOS는 다르다 — 읽기 전에
`startDownloadingUbiquitousItem`을 불러야 하고, `NSMetadataQuery`로 도착을
지켜봐야 한다. 이 층은 Tauri iOS 플러그인(Swift)으로 만들고, Rust `notes-sync`는
"파일이 자리에 있다"는 전제만 유지한다. — 버린 것: Rust에서 직접 objc 호출.
플러그인 경계가 더 얇고 테스트가 쉽다.

**모바일 셸은 새로 그린다. 편집기 부품은 재사용한다.** 사이드바·분할 창·단축키
힌트는 데스크톱 전용이다. 탭 바(Today · Journals · Pages · Search) 네 개로
바꾸고, `NotesOutline`·store·저널 로직은 그대로 가져온다. 키보드가 화면 절반을
먹으므로 들여쓰기·완료 토글은 키보드 액세서리 바로 옮긴다.

## 3. 화면 구성 (시안 프레임과 1:1)

| 화면 | 내용 |
|---|---|
| ① Today | 앱 시작 화면. 날짜 머리글 + ←/→, carry-over 알림 줄, 아웃라인, 편집 중 키보드 액세서리 바 |
| ② Journals | 날짜 내림차순 피드. 맨 위 하루만 편집 가능, 7일씩 더 보기 |
| ③ Pages | 저널 제외 페이지 목록, 별표 우선 |
| ④ Page 상세 | 아웃라인 + 이동 경로(breadcrumb), 불릿 눌러 zoom |
| ⑤ Search | 검색 입력 + `date:` 칩, 결과는 페이지별 묶음 |
| ⑥ 첫 실행 | iCloud 상태 확인 → vault 생성/연결, 동기화 상태 배지 |

## 4. 위험

- **iCloud 내려받기 지연**: 큰 vault를 새 기기에서 처음 열면 파일이 전부
  dataless다. 첫 화면은 SQLite 캐시가 없으니 "내려받는 중" 상태가 필요하다.
- **WKWebView 모바일 키보드**: contenteditable 포커스와 소프트 키보드의
  viewport 변화는 데스크톱이 안 밟은 영역이다. 첫 수직 슬라이스에서 실기기로
  일찍 확인한다.
- **백그라운드 동기화 없음**: iOS는 앱이 떠 있을 때만 파일을 본다. v1은 이를
  받아들이고, 앞에 올 때 한 번 스캔한다.
