그 위에 얹힌다.

## 2. 계획에서 바뀐 것과 그 근거

계획 문서의 문장을 실제로 뒤집은 것들만 적는다. 사소한 조정은 뺐다.

| 바뀐 것 | 원래 계획 | 지금 | 근거 |
|---|---|---|---|
| 노드 20,000 캡의 자리 | `NotesTree::validate` | 파서·(M4) 방출 | 명령은 하이드레이트한 부분 트리에 plan한다 — 거기서 센 수는 커 가는 페이지를 못 보고, 반대로 그 페이지를 고치는 대량 삭제를 거절한다 |
| `SyncVaultStatus` 계약 타입 | 만든다 | **안 만든다** | get이 돌려줄 것이 경로 하나뿐이다. 계약 타입이 실제로 필요한 자리는 set의 반환값이었고 그건 `SyncVaultFolderState`가 됐다 |
| 병합의 자리 | 트레이트 포트 | 호출자가 연 트랜잭션 위의 라이브러리 함수 | 노드 상태를 트레이트로 주고받으면 문서당 수천 왕복이라 질의 예산에 닿을 수 없다 |
| 적용 질의 예산 ≤8문 | 일괄문으로 묶는다 | **에코 경로 상수문 + 변경분당 상수문** | 자리 계산이 앞선 쓰기에 의존해 묶이지 않는다. M6.3 게이트는 이 형태로 잡는다 |
| 이미지 인입 | a~e 어디에도 없었다 | M3.1a 소유 | 행이 없으면 정규화 내용이 영원히 어긋나 **같은 파일을 읽을 때마다 편집으로 보인다** |
| 이미지 경계 검사 | (없음) | 파서 소유 | 포맷의 사실이라 격리 사유로 답해야 한다. 병합까지 흘러가면 DB 제약이 읽을 수 없는 문자열로 죽인다 |
| 스펙 §11 golden 초안 | 그대로 fixture | 이스케이프 적용판으로 정정 | §4.1이 ASCII 문장부호 전부에 `\`를 붙인다. 초안대로 갔으면 모든 golden이 영원히 비정규형이고 파일을 읽을 때마다 write-back이 돌았다 |
| 스키마 DDL 위치 | `schema.rs` 리터럴 | `schema.sql` + `include_str!` 양쪽 | 병합 테스트가 의존 방향을 안 깨고 진짜 DDL을 얻는 유일한 길 |

번들 예산은 1KiB씩 올렸다. 카드를 지연 로드해 2,351/2,699바이트를 돌려받고도
남은 600을 올릴 수밖에 없었는데, 커밋별로 재어 보니 **이 작업이 프런트를 건드리기
전에 이미 2바이트 초과** 상태였다.

## 3. 교훈 — 무엇이 반복해서 우리를 속였나

여덟 라운드에서 나온 결함을 종류로 묶으면 셋이다. 셋 다 "테스트가 초록인 채로"
숨어 있었다.

### 교훈 1. 초록은 통과의 증거가 아니다. **규칙을 지워 red를 봐야 증거다.**

지금까지 이 절차가 잡은 가짜 통과가 **열두 건**이다. 몇 가지 모양:

- 테스트가 **엉뚱한 이유로** 통과한다. `../assets/` 링크 격리 테스트는 모든
  `../`가 실패했기 때문에 통과하고 있었다 — 탈출과 정당한 상승을 구분하지
  못했고, 그래서 **이미지가 든 trash 파일이 통째로 읽히지 않는** 결함을 덮었다.
- 규칙이 **중복**이라 지워도 다른 규칙이 받는다. JSON `\n` 전용 분기를 지워도
  초록이었다 — 실제로 일하는 건 제어문자 범위 폴백이었다.
- 변이가 **무효**다. 바꾼 값이 원래 값과 같아 아무것도 안 바뀐 채 "잠겼다"고
  읽었다. 두 번 있었다.
- 테스트가 **정착 전에 단언**한다. `waitFor`는 처음 던지지 않은 시점에 통과해서,
  "카드가 안 보인다"가 카드를 띄울 읽기가 풀리기도 전에 성립했다.
- 픽스처가 **자기 자신을 단언**한다. root를 빈 스탬프로 심어 두니 삽입 트리거가
  dirty를 찍었고, dirty 단언이 병합이 아니라 픽스처를 읽고 있었다.

**앞으로**: 규칙 하나를 넣을 때마다 되돌려 red를 눈으로 본다. 변이가 실제로
적용됐는지(앵커 일치) 확인하고, 초록이면 "규칙이 중복인가, 테스트가 약한가"를
먼저 묻는다. M3.1e 이후 모든 항목에 그대로 적용한다.

### 교훈 2. **없는 것을 있는 주장으로 바꾸지 마라.** 데이터가 조용히 깨진다.

가장 비쌌던 결함 셋이 전부 이 모양이었다.

- 페이지 README는 **위치를 말하지 않는다**(페이지의 자리는 home의 줄이다).
  그 부재를 "root의 첫 자식"으로 읽으니, 페이지 파일을 **다시 읽기만 해도** 앞으로
  끌려가며 재스탬프됐고 그 스탬프가 fleet 전체에서 이겼다.
- 손으로 친 줄은 **아직 id가 없다**. 뒤 형제가 "누구를 따르는지" 기록하는 시점이
  발급보다 앞서니, 그 형제가 "첫 번째"라고 주장하며 문서가 재배열됐다.
- 손으로 적은 미래 `max_hlc`를 **믿었다**. 부팅 클록이 그걸 흡수하면 이후 모든
  로컬 편집이 미래로 도장 찍힌다.

**앞으로**: 새 필드·새 증거를 다룰 때 "이 값이 없다는 것"과 "이 값이 기본값이라는
것"을 코드에서 구분한다. M3.1e의 split 줄이 정확히 이 함정이다 — 줄은 존재·위치만
말하고 상태는 **말하지 않는다**. `Option`으로 들고 다니고, 기본값으로 접지 않는다.

### 교훈 3. **스탬핑 트리거는 우리 편이 아니다.** 쓰기마다 어떤 컬럼을 건드렸는지 센다.

세 번 물렸다.

- 같은 t를 지킨 채택: UPDATE 트리거는 hlc가 **안 바뀌었을 때** 발화한다 —
  타이브레이크가 정확히 그 조건이라 원격 스탬프가 매번 로컬 fresh로 갈렸다.
- 형제 재간격: `sort_key`가 트리거의 컬럼 목록에 있어 형제 **전부**가 재스탬프됐다.
- trash 자리표시: 빈 스탬프로 넣자 삽입 트리거가 찍어서, 자리표시가 기다리던
  진짜 문서를 이겼다.

**앞으로**: `notes_nodes`에 쓰는 새 경로마다 (a) 트리거 컬럼 목록과 겹치는지,
(b) 겹치면 3단계 패턴(쓰기 → 스탬프 복원 → dirty 정리)을 태웠는지, (c) 원래
dirty였던 행을 지우지 않는지 세 가지를 확인한다. M4 exporter가 같은 표를 쓴다.

### 교훈 4. 리뷰에 **거짓 보고를 하지 마라.**

스크래치 파일을 히스토리에서 걷어냈다고 보고했는데, 바로 다음 커밋에서
`git add -A docs`로 다시 들어가 있었다. 리뷰가 그걸 잡았다.

**앞으로**: 커밋 전 `git status --short`를 눈으로 읽고, "제거했다"고 말하기 전에
브랜치 전 커밋을 확인한다(`git log --name-only | grep`). 작업용 스크래치는
`.git/info/exclude`에 넣는다. **이 문서를 쓰는 지금 전용 worktree로 옮긴 것도
같은 이유다** — 메인 작업 트리에 남의 미커밋 파일이 섞이지 않는다.

### 교훈 5. 설계는 구현이 반증한다. **문서를 고쳐서 남긴다.**

병합 설계는 §1.5와 §1.5.1로 개정 12건을 실었다. 설계가 말하지 않은 자리
(문서 루트가 사다리에 어떻게 들어가는가)가 가장 비싼 결함을 냈다.

**앞으로**: 리뷰가 "설계가 틀렸다"고 하면 코드만 고치고 넘어가지 않는다. 같은
커밋에서 설계 문서에 개정 항목을 적는다 — 다음 항목의 구현자가 읽는 것은 코드가
아니라 문서다.

## 4. 남은 항목에 이 교훈을 어떻게 쓰나

| 항목 | 이 교훈이 걸리는 자리 |
|---|---|
| **M3.1e** split 권위 + 대수 property | 교훈 2가 정면이다. 줄은 존재·위치만, 상태는 자식 frontmatter. 자식이 아직 안 온 상태(`sync_documents` 행 부재)를 **부재로** 들고 다닌다. property 3종은 교훈 1의 자동화판이다 — 생성기가 만든 반례가 곧 red다 |
| **M3.2** 워커 접합 | 교훈 3. revision·`path` 재계산이 같은 트랜잭션이어야 하고, 우회 경로 테스트(`a_commit_with_the_pre_merge_revision_is_rejected`)가 그걸 잡는다 |
| **M3.3** undo 배리어 | 교훈 2. "외부에서 흡수한 변경"과 "내가 한 편집"을 구분하는 증거가 무엇인지 먼저 못 박는다 |
| **M3.4/M3.5** 충돌 IPC·화면 | `loser_json`의 wire 계약이 이미 M3.1a·b에서 두 번 틀렸다. 소비자 테스트가 그 형태를 잠근다 |
| **M4** 방출 | 교훈 3(같은 표에 쓴다) + 정규화 내용 함수 재사용(`sync_node_exports.content_hash`는 병합의 digest와 **같은 함수**다) |
| **M5** 감시 | 교훈 2. 이벤트는 무조건 해시, stat 단축은 전체 스캔만 — "안 바뀐 것 같다"를 "안 바뀌었다"로 읽지 않는다 |
| **M6** 검증 | 교훈 1의 최종판. 성능은 시간이 아니라 **카운터**로 잰다 |

## 5. 작업 방식 — 지금부터

- 브랜치와 **전용 worktree**에서 작업한다(`.worktrees/sync-m3e`). 메인 작업 트리는
  건드리지 않는다.
- 항목당 1커밋. 커밋 전에 `git status --short`를 읽는다.
- 항목마다: red 확보 → 구현 → **규칙별 제거 검증** → 게이트 → 커밋 → 적대적 리뷰.
- 리뷰가 설계를 반증하면 코드와 문서를 같은 커밋에서 고친다.
