# Notes Data Repair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an in-app repair action that backs up and replaces legacy recovery sort keys that exceed JavaScript's safe-integer range, then reloads Notes without deleting user content.

**Architecture:** A focused Rust sync module owns legacy-key detection, verified backups, SQLite repair, export, rollback, and the repair report. One Tauri command exposes the operation; a strictly validated TypeScript adapter and reusable React action place it in the write-authority error banner and Notes data settings.

**Tech Stack:** Rust, rusqlite, cap-std, Tauri 2 IPC, TypeScript 6, React 19, Base UI, Vitest, Testing Library.

## Global Constraints

- Repair only exact legacy 60-bit UUID-prefix keys and normal 1024-step sibling
  values derived from an exact legacy anchor under the same parent.
- The replacement uses the first 52 UUID bits and never exceeds `9_007_199_254_740_991`.
- Back up every existing Notes Markdown file before overwriting it.
- Do not delete Notes, attachments, Trash history, or unrelated Vault files.
- Abort without changes when an unsafe sort key does not match the known
  legacy pattern or cannot be projected while preserving sibling order.
- Do not add a Notes schema version, file-format version, migration, or dependency.
- Both UI entry points call the same `notes_repair_data` command.
- A no-op repair does not create a backup.
- A successful repair leaves sync stopped until the frontend reloads the app.

use uuid::Uuid;

pub(crate) const JAVASCRIPT_MAX_SAFE_INTEGER: i64 = 9_007_199_254_740_991;
const LEGACY_UUID_PREFIX_HEX_DIGITS: usize = 15;
const SAFE_UUID_PREFIX_HEX_DIGITS: usize = 13;

fn uuid_prefix_sort_key(node_id: &str, digits: usize) -> Result<i64, NotesError> {
    let canonical = Uuid::parse_str(node_id)
        .map_err(|_| "A recovered Notes node ID is invalid.".to_string())?
        .simple()
        .to_string();
    let prefix = u64::from_str_radix(&canonical[..digits], 16)
        .map_err(|_| "A recovered Notes node ID is invalid.".to_string())?;
    i64::try_from(prefix)
        .map_err(|_| "A recovered Notes sort key is too large.".to_string().into())
}

    uuid_prefix_sort_key(node_id, SAFE_UUID_PREFIX_HEX_DIGITS)

    uuid_prefix_sort_key(node_id, LEGACY_UUID_PREFIX_HEX_DIGITS)

In `repair.rs`, query every unsafe node before mutating:

```rust
#[derive(Debug, Clone, PartialEq, Eq)]
struct RepairRow {
    id: String,
    old_sort_key: i64,
    new_sort_key: i64,
}

fn load_repair_rows(connection: &rusqlite::Connection) -> Result<Vec<RepairRow>, String> {
    let mut statement = connection
        .prepare(
            "SELECT id, sort_key FROM notes_nodes
             WHERE sort_key > ?1 OR sort_key < ?2
             ORDER BY id",
        )
        .map_err(|error| format!("Could not inspect Notes ordering data: {error}"))?;
    let rows = statement
        .query_map(
            rusqlite::params![
                JAVASCRIPT_MAX_SAFE_INTEGER,
                -JAVASCRIPT_MAX_SAFE_INTEGER
            ],
            |row| Ok((row.get::<_, String>(0)?, row.get::<_, i64>(1)?)),
        )
        .map_err(|error| format!("Could not read Notes ordering data: {error}"))?
        .collect::<Result<Vec<_>, _>>()
        .map_err(|error| format!("Could not read Notes ordering data: {error}"))?;
    drop(statement);

    rows.into_iter()
        .map(|(id, old_sort_key)| {
            let legacy = legacy_recovery_sort_key(&id).map_err(|error| error.to_string())?;
            if old_sort_key != legacy {
                return Err(format!(
                    "Notes node {id} has an unsupported unsafe sort key."
                ));
            }
            Ok(RepairRow {
                new_sort_key: safe_recovery_sort_key(&id)
                    .map_err(|error| error.to_string())?,
                id,
                old_sort_key,
            })
        })
        .collect()
}
```

- [ ] **Step 4: Implement verified backup, transaction, export, and rollback**

Use one unique `repair-<millis>-<uuid>` directory. Revalidate the app lock before and after each filesystem operation. Apply each row with:

```rust
transaction.execute(
    "UPDATE notes_nodes SET sort_key = ?1 WHERE id = ?2 AND sort_key = ?3",
    rusqlite::params![row.new_sort_key, row.id, row.old_sort_key],

The existing `notes_nodes_hlc_au` trigger restamps HLC and marks the owning export dirty. Resolve pending export targets after the updates but before commit, back up each existing target file byte-for-byte, and commit only after every backup verifies.

After commit, call the injected flush closure. On failure:

1. start a compensating transaction;
2. restore every `old_sort_key` with an ID-and-new-value guard;
3. commit, letting triggers mark rollback exports dirty;
4. restore every preexisting file with `write_atomic_file(path, bytes, true)`;
5. remove only repair-created files that were recorded as absent;
6. return the original export error plus the backup path if any restoration fails.

After a successful flush, call `crate::notes::repository::load_workspace` for the active scope and assert every returned node and attachment sort key is a safe integer before returning `NotesRepairReport`.

export async function notesRepairData(
  vaultPath: string
): Promise<NotesDataRepairReport> {
  const result = await invokeNotes<unknown>("notes_repair_data", { vaultPath });
  if (
    !isPlainRecord(result) ||
    !hasExactKeys(result, [
      "repairedNodeCount",
      "backedUpFileCount",
      "backupPath"
    ]) ||
    !Number.isSafeInteger(result.repairedNodeCount) ||
    result.repairedNodeCount < 0 ||
    !Number.isSafeInteger(result.backedUpFileCount) ||
    result.backedUpFileCount < 0 ||
    (result.backupPath !== null && typeof result.backupPath !== "string") ||
    (result.repairedNodeCount === 0 &&
      (result.backedUpFileCount !== 0 || result.backupPath !== null))
  ) {
    throw new Error("Notes data repair returned an invalid report.");
  }
  return result as unknown as NotesDataRepairReport;
}
```
