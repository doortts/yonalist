# 저널(Journal) 기능 설계

2026-08-21 · 브랜치 `claude/logseq-journal-feature-db150a` · 시안
[2026-08-21-journal-feature-mockup.html](../mockups/2026-08-21-journal-feature-mockup.html)

설계자는 원래 Fable 5여야 하나 사용량 한도로 실행하지 못했다. 설계·구현을 Opus 5가
맡고 검토만 별도 컨텍스트의 에이전트에 맡긴다. 같은 모델이 인접 단계를 맡은
것이므로 `fable-opus-loop`에서 벗어난 지점으로 기록한다.

## 1. 계약

| 항목 | 내용 |
|---|---|
| 목표 | 날짜가 제목인 페이지를 하루 단위 기록 공간으로 쓰고, 사이드바·피드·날짜 토큰·참조 목록으로 그 하루를 오간다 |
| 비대상 | `[[페이지]]` 링크와 backlink 그래프, 템플릿, SCHEDULED/DEADLINE, 쿼리 문법, `journals/` 전용 vault 폴더 |
| 영향 범위 | 프론트엔드 전부. Rust는 `date:` 필터의 범위 문법 한 곳뿐 |
| 데이터 결정 | 스키마 변경 없음. 저널 여부는 페이지 제목에서 파생한다 |
| Undo/Redo | 저널 페이지 생성은 지금 페이지 생성과 같은 경로다. 이어받기는 `moveNodes` 한 번이라 되돌리기 한 번에 되돌아간다 |
| 직접 확인 | `npm run dev` 프리뷰에서 Today → 입력 → Journals 피드 → 날짜 토큰 클릭 → 참조 목록 |

## 2. 정한 것과 버린 것

**저널 판정은 제목에서 파생한다.** `PageSummary.title`이 `YYYY-MM-DD` 하나로만
이루어졌고 실제 달력에 있는 날짜면 저널이다. 스키마도 IPC도 늘지 않고 vault 폴더
이름(`2026-08-21-<yid>`)만 봐도 읽힌다. — 버린 것: `notes_nodes`에 컬럼 추가.
릴리스 전 스키마 고정 원칙에 걸리고, 얻는 것은 "보통 페이지 제목을 날짜로 바꾸면
저널이 된다"를 막는 것뿐이다. Logseq도 파일 이름이 곧 날짜다.

**같은 날짜가 둘이면 페이지 순서에서 먼저 오는 쪽을 연다.** 동기화로 두 기기가 같은
날을 각각 만들면 생길 수 있다. 조용히 하나를 고르되 다른 하나도 `Journals` 목록에
그대로 남아 사람이 합칠 수 있다. — 버린 것: 자동 병합. 병합은 되돌릴 수 없다.

**피드는 맨 위 하루만 편집한다.** `NotesOutline`은 페이지 하나에 묶인 판이고
`paneId`는 `primary`/`secondary` 둘뿐이다. 날마다 판을 하나씩 띄우면 선택·드래그·
되돌리기 등록이 N벌로 늘어난다. 오늘은 진짜 판을 띄우고 지난 날은 `queryForest`로
읽어 읽기 전용으로 그린다. 지난 날 줄을 누르면 그날 페이지가 열린다. 시안의 그림도
캐럿은 오늘에만 있다. — 버린 것: 날짜마다 편집 가능한 판. 판 등록기를 N개로
고치는 값이 이 기능이 지불할 값을 넘는다.

**피드 창은 7일씩 늘린다.** 400일치 vault에서 처음부터 다 그리면 첫 화면이 죽는다.
`queryForest`는 뿌리 여러 개를 한 번에 읽으므로 보이는 날만 넘긴다.

**참조는 이미 있는 `date:` 검색이다.** `SearchHit.pageId`가 출처 페이지를 들고 오니
그 저널 자신의 `pageId`를 빼면 "다른 곳에서 이 날을 가리킨 줄"이 남는다. 저널의 제목
자체도 색인에 들어가므로 자기 페이지 제외는 반드시 필요하다. — 버린 것: SQL에서
subtree를 빼는 새 필터. 클라이언트가 이미 답을 들고 있다.

**이어받기는 앞선 7일만 본다.** 반년 전 안 끝난 줄까지 끌고 오면 오늘 페이지가
쓰레기통이 된다. 옮기기는 `moveNodes` 한 번이라 되돌리기도 한 번이다. — 버린 것:
복사. 두 곳에 같은 할 일이 남으면 어느 쪽이 진짜인지 알 수 없다.

**UI 문구는 영어다.** 앱의 다른 문구가 전부 영어다(`New page`, `Pages`, `Starred`).
시안의 한국어는 설명문이었지 제품 문구가 아니다. 요일만 `Intl.DateTimeFormat`으로
기기 로케일을 따른다.

## 3.1 리뷰 뒤에 남긴 한계

적대적 리뷰(2026-08-21)가 잡은 것 중 고치지 않고 남긴 것들이다. 남긴 이유를 함께
적는다.

- **같은 날짜가 둘일 때 두 번째 페이지.** `Journals` 칸에는 목록이 없고 `Today`·
  `Journals`·달력만 있다. 지난 날이면 피드의 `Earlier days`에 둘 다 나오지만 오늘이
  겹치면 두 번째는 검색으로만 닿는다. 두 기기가 같은 날을 각각 만든 경우에만 생기고,
  목록을 하나 더 만드는 값보다 드물다.
- **`⌘⇧J`로 없던 날을 열면 되돌리기가 두 번이다.** 페이지 만들기와 첫 줄 만들기가
  각각 커맨드라 한 번 되돌리면 빈 날 페이지가 남는다. 한 번 더 되돌리면 페이지도
  사라진다. 둘을 한 그룹으로 묶으려면 모든 쓰기가 지나는 커맨드 길목을 고쳐야 해서,
  이 기능이 지불할 값을 넘는다.
- **앞으로 쓴 날짜는 피드에 없다.** 피드는 오늘보다 이전 날만 싣는다. 오늘 위에 미래
  날짜를 쌓으면 "어제까지 무엇을 했나"를 읽는 화면이 아니게 된다.
- **이어받기 개수는 다른 기기의 동기화를 따라오지 않는다.** 되돌리기·다시 하기와 이
  화면이 직접 옮긴 것에는 반응하지만, 다른 기기가 지난 날에 To-do를 되돌려 놓은
  경우에는 그 날을 떠났다 돌아와야 다시 센다.
- **`⌘⇧J`의 빈 줄 판정은 실린 창만 본다.** 한 페이지에 최상위 줄이 80개를 넘으면
  마지막 줄이 아니라 창의 마지막 줄을 본다. 최악이 빈 줄 하나 더 생기는 것이라 둔다.

## 4. 위험

- **피드의 읽기 전용 표현이 아웃라인과 달라 보인다.** 토큰(태그·날짜)은 같은
  `outlinePresentation`으로 그려 차이를 줄인다. 접힘·이미지·정렬 번호는 그리지 않는다.
- **프리뷰 API의 `search`가 `date:` 필터를 모른다.** 참조 목록을 프리뷰에서 확인하려면
  `previewApi.search`가 `date:`를 알아야 한다. 항목 6에서 같이 손본다.
- **저널이 늘면 `state.pages`도 늘어난다.** 지금 boot는 페이지 전부를 싣는다. 수천 일이
  쌓이면 boot 응답이 커지는데, 이 설계가 만드는 문제는 아니고 페이지 목록 자체의
  문제다. 관찰 대상으로만 남긴다.
