# 완료는 선언이다 — ⌘↩ 3단계

작성 2026-08-19. Fable 5 한도 초과로 설계도 Opus 5가 썼다.

## 무엇이 바뀌는가

지금 완료는 **집계**다. 행이 완료라고 말하면 그 아래가 전부 끝났다는 사실이고, 그래서
전파가 하위를 덮고 조상 판정이 가지 전체를 읽는다.

앞으로 완료는 **선언**이다. 행의 완료 표시는 그 행이 하는 말이고, 아래에 열린 행이
남아 있어도 된다. 못 하게 된 일, 더 필요 없어진 일은 열린 채로 두고 부모만 닫는다.

이 상태는 이미 모델이 허용한다. 붙여넣기는 잘라낸 상태를 그대로 갖고 오고, 동기화는
다른 기기의 상태를 그대로 받고, 빈 행은 부모를 열지 않는다. 손으로 만들 수 없었을 뿐이다.

## ⌘↩ 3단계

같은 행에서 ⌘↩을 누를 때마다 한 칸씩 돈다. 단계는 저장된 트리에서 서버가 읽는다.
클라이언트는 페이지의 창만 들고 있어 접힌 자식을 못 볼 수 있고, 단계를 잘못 고르면
엉뚱한 이동이 나간다.

| 지금 상태 | 누르면 | 하는 일 |
| --- | --- | --- |
| 미완료 | 1단계 | 자기만 완료. 자식은 손대지 않는다 |
| 완료 + 미완료 자식이 하나라도 있음 | 2단계 | 직계 자식들의 현재 완료 상태를 기억하고 전부 완료로 |
| 완료 + 직계 자식 전부 완료(자식이 없어도 여기) | 3단계 | 자기를 미완료로, 직계 자식은 2단계에서 기억한 상태로 되돌림 |

- 자식이 없는 행은 1단계와 3단계만 돈다. 흔한 켜고 끄기다.
- 2단계는 **직계 자식만** 쓴다. 자식의 완료 표시는 그 자식의 선언이고, 그 아래는
  그 자식의 소관이다.
- 3단계의 기억이 없으면(중간에 다른 변경이 끼면) 자기만 미완료로 바뀌고 자식은 그대로
  남는다. 되돌릴 값이 없으면 아무 것도 지어내지 않는다. ⌘Z는 그대로 듣는다.
- 누르고 있는 반복 입력은 한 번으로 센다. 3단계가 눌린 채로 두 바퀴 도는 것을 막는다.

## 자동 규칙은 상태가 아니라 전이에 붙는다

선언 모델에서 "완료된 부모 + 열린 자식"은 **정상 상태**다. 그러니 자동 규칙이 그 상태를
보고 움직이면 안 된다. 무언가 **바뀌는 순간**에만 움직인다.

| 전이 | 자동으로 하는 일 | 근거 |
| --- | --- | --- |
| 행이 완료로 바뀜 | 부모의 직계 자식이 이제 전부 완료면 부모도 완료, 위로 계속 | 마지막 자식을 끝냈으면 부모도 끝난 것 |
| 완료였던 행이 미완료로 바뀜 | 부모의 완료를 해제, 위로 계속 | 방금 다시 열린 일이 있는데 부모가 끝났다고 할 수 없다 |
| 내용이 있는 행이 새로 놓임(생성·이동·휴지통 복원) | 위의 완료된 행들을 해제 | 새로 도착한 일은 선언을 무효로 한다(2026-08-19 요청) |
| 완료 안 된 행이 떠남(휴지통·다른 부모로 이동) | 남은 직계 자식이 전부 완료면 부모 완료, 위로 계속 | 마지막 걸림돌이 사라졌다(2026-08-19 요청) |

**손으로 열린 채 남겨 둔 자식은 아무 전이도 아니다.** 그래서 부모의 선언이 유지된다.
이미 내용이 있는 행의 텍스트를 고치는 것도 전이가 아니다(빈 행 → 내용만 전이). 버려둔
행의 오타를 고쳐도 부모는 닫힌 채로 있다.

## 깊은 검사가 사라진다

조상 판정이 "가지 전체가 완료인가"에서 "**직계 자식이 전부 완료인가**"로 바뀐다.
완료된 자식은 자기 아래를 가린다 — 그게 선언이라는 말의 뜻이다.

따라오는 것:

- 명령이 읽는 창이 **페이지 전체에서 조상 경로 + 각 조상의 직계 자식**으로 줄어든다.
  어제 측정한 5천 행 83ms, 5만 행 985ms가 페이지 크기와 무관해진다. `node_paths`
  EXISTS 계획, 복합 인덱스, 배제 범위, proptest 전부 필요 없어진다.
- 이 세션에서 리뷰가 반복해 잡아낸 결함 계급 — 창 밖의 행을 없는 행으로 읽고 조상을
  잘못 닫는 것 — 이 사라진다. 직계 자식은 언제나 창에 있다.
- 뒤집히는 계약이 하나 있다. 지금은 완료된 자식 아래 열린 손자가 조상 완료를 막는다
  (`tree_commands.rs`의 `an_ancestor_todo_stays_open_while_a_todo_further_down_is_open`).
  앞으로는 완료된 자식의 말을 믿는다.

## 아이템

각 항목은 커밋 하나, 먼저 빨간 테스트부터.

1. **`SetCompleted`가 전파를 그만둔다** — 자기 행만 쓰고, 조상 규칙은 직계 자식으로
   판정한다. `cascade_completed`의 하위 전체 쓰기가 사라지고 `descendant_ids`는 판정에서
   빠진다. 체크박스·선택 일괄·슬래시·메뉴가 전부 이 명령이라 A11이 같이 성립한다.
   테스트: `crates/notes-core/tests/tree_commands.rs`
   `completing_a_row_leaves_its_children_as_they_are`,
   `an_ancestor_follows_once_its_own_children_are_done`,
   `a_finished_child_hides_the_open_row_under_it`
   기존 계약을 뒤집는 테스트: `ticking_a_row_settles_every_descendant_whatever_its_marker`,
   `an_ancestor_waits_for_the_whole_branch_below_it`,
   `an_ancestor_todo_stays_open_while_a_todo_further_down_is_open`,
   `completing_a_selection_settles_each_listed_row_s_own_chain`,
   `crates/notes-sqlite/tests/todo_cascade.rs`의 체인 테스트 전부.
2. **`CycleCompleted { id }`** — 서버가 저장된 트리에서 단계를 읽고 세 이동 중 하나를
   낸다. 2단계의 기억은 그 명령이 남긴 undo 항목의 inverse이고, 3단계는 그 inverse를
   앞으로 가는 패치로 다시 커밋하면서 자기 행을 미완료로 바꾼다. 항목이 더 이상 맨 위가
   아니면(다른 변경이 끼면) 자기 행만 바꾼다. 이 세션에 이미 있는 "방금 누른 틱 되돌리기"
   기계를 그대로 쓴다.
   테스트: `crates/notes-sqlite/tests/completion_cycle.rs`
   `the_first_press_finishes_only_the_row_itself`,
   `the_second_press_finishes_the_children_it_names`,
   `the_third_press_hands_the_children_back_their_own_states`,
   `a_row_with_no_children_turns_over_in_two_presses`,
   `an_edit_in_between_leaves_the_children_alone`
3. **자동 규칙을 전이로 다시 맞춘다** — 새 내용 도착(A9)과 떠남(A10) 판정을 직계 자식으로
   바꾸고, 손으로 남긴 열린 자식이 아무 전이도 아니라는 것을 잠근다.
   테스트: `crates/notes-core/tests/tree_commands.rs`
   `a_row_left_open_by_hand_keeps_the_parent_finished`,
   기존 `a_new_row_under_a_finished_branch_opens_it_again`,
   `trashing_the_last_open_row_finishes_the_branch_above_it` 유지.
4. **창을 줄인다** — `collect_cascade_branch`와 `collect_departure_context`의 페이지 전체
   읽기를 조상 경로 + 각 조상의 직계 자식으로 바꾼다. `cascade_root`가 사라진다.
   테스트: `crates/notes-sqlite/tests/completion_window.rs`
   `a_press_reads_the_row_its_children_and_the_path_above_it`(창 크기가 페이지 크기와
   무관함을 노드 수로 단정), 그리고 `bench-fixtures`에 5만 행 페이지 한 번 누르기 상한.
5. **프리뷰 미러** — 세 이동과 직계 자식 판정을 `previewTree.ts`/`previewApi.ts`에 같은
   모양으로.
   테스트: `apps/desktop/src/preview/previewApi.test.ts`
   `turns a row over in three presses`
6. **⌘↩ 배선과 문서** — `outlineKeyboard`의 `toggleComplete` 의도가 `cycleCompleted`로

   적는다.
   테스트: `apps/desktop/src/outline/outlineKeyboard.test.ts`

## 결정과 이유

1. **단계는 서버가 읽는다** — 클라이언트는 창만 들고 있고 접힌 자식은 창에 없을 수 있다.
   단계를 클라이언트가 고르면 접힌 가지를 가진 행에서 엉뚱한 이동이 나간다.
2. **단계를 저장하지 않고 트리에서 읽는다** — 저장하면 다른 기기·다른 창·앱 재시작과
   어긋난다. "완료됐나"와 "직계 자식이 전부 완료됐나" 두 질문으로 세 단계가 갈리고,
   둘 다 트리가 답한다. 자식이 이미 전부 완료였던 행은 2단계가 할 일이 없어 두 칸만
   도는데, 그게 사람이 기대하는 켜고 끄기다.
3. **3단계의 기억은 undo 항목의 inverse** — 2단계 패치의 inverse가 곧 "직전 자식 상태"다.
   새 저장 필드도, 새 도메인 명령도 필요 없다. 이 세션에서 이미 그 방식으로 돌고 있다.
4. **체크박스는 자기 행만** — 상자는 두 상태를 그리는 물건이다. 세 칸은 ⌘↩과 행 메뉴의
   일이다.
5. **자동 규칙은 전이에만** — 선언 모델에서 "완료된 부모 + 열린 자식"은 정상 상태이므로,
   상태를 보고 움직이는 규칙은 선언을 되돌려 버린다. 전이에 붙이면 이 세션의 두 요청
   (새 행이 열고, 떠남이 닫는다)과 새 요청이 함께 산다.
6. **제3 상태는 안 만든다** — 버린 일을 버린 일로 알아보게 하려면 취소 상태와 markdown
   표기, 렌더링, 동기화가 다 늘어난다. 열린 채로 두는 것으로 부족하다는 게 드러날 때
   만드는 편이 싸다.

## 알아둘 결과

- 내보낸 markdown에 `- [x]` 부모 아래 `- [ ]` 자식이 정상으로 남는다. 내보내기는 행마다
  쓰므로 코드 변경은 없다.
- 진행 표시(`buildTodoProgressMap`)는 지금처럼 상자 달린 행을 센다. 완료된 부모 아래
  2/5가 남을 수 있고, 그게 선언 모델의 정직한 표시다.
- 이 세션 첫 요청("상위 완료 시 하위 전부 완료")은 1단계가 아니라 **2단계**가 된다.
  한 번에 되던 일이 두 번이 되는 셈이라, 이게 아깝다면 1단계와 2단계를 뒤집는 선택도
  있다(첫 누름이 전파, 두 번째가 자기만) — 다만 요청 문장은 지금 표의 순서다.
