# 이미지 블릿 텍스트 기준선 안정화 설계

## 목표

이미지와 텍스트가 함께 있는 블릿에서 커서를 옮기거나 이미지·텍스트를 선택해 편집 상태가 바뀌어도 텍스트의 세로 위치가 변하지 않게 한다.

## 현재 원인

`ImageAtomEditor`는 같은 텍스트를 두 표현으로 렌더링한다.

- 비편집 상태: 토큰 표시를 위한 절대 배치 오버레이
- 편집 상태: 브라우저 선택과 IME 입력을 담당하는 원본 텍스트

일반 블릿의 텍스트 영역에는 `padding-block: 2px`가 있다. 원본 텍스트는 이 패딩 안에서 배치되지만 오버레이 컨테이너는 `position: absolute; inset: 0`으로 패딩 박스의 위쪽부터 시작한다. 따라서 비편집 오버레이가 원본 텍스트보다 2px 위에 있고, 포커스나 선택으로 원본 텍스트가 나타날 때 글자가 2px 아래로 이동한다.

## 선택한 설계

오버레이 컨테이너가 부모 텍스트 영역의 계산된 패딩을 상속하게 한다. 기존 절대 배치와 표시 전환은 유지하고 `padding: inherit`만 더해 오버레이와 원본 텍스트가 같은 콘텐츠 시작점을 사용하게 한다.

이 방식은 일반 블릿의 현재 2px 패딩을 정확히 반영하고, 패딩이 없는 서브 페이지 제목에서도 추가 오프셋을 만들지 않는다. 향후 텍스트 영역 패딩이 바뀌더라도 두 표현이 함께 움직인다.

## 대안과 제외 이유

1. 일반 블릿 텍스트 영역의 패딩을 제거한다.
   - 기존 행 높이와 블릿 정렬까지 바뀌므로 영향 범위가 넓다.
2. 편집 상태에만 `translateY(-2px)` 같은 보정값을 둔다.
   - 현재 값에 결합된 증상 보정이며 다른 문맥이나 향후 패딩 변경에 취약하다.

## 완료 조건

- 이미지 뒤에 텍스트가 있는 일반 블릿에서 포커스 전후 텍스트의 세로 위치가 같다.
- 이미지 앞에 텍스트가 있는 일반 블릿에서도 같은 규칙이 적용된다.
- 텍스트 선택과 이미지 선택으로 편집 상태가 바뀌어도 세로 이동이 없다.
- 서브 페이지 제목의 이미지·텍스트 배치에는 새 오프셋이 생기지 않는다.
- 이미지 크기, 이미지 선택 테두리, 텍스트 입력, 토큰 표시, IME 처리는 그대로 유지된다.

## 테스트와 직접 확인

- `ImageAtomEditor.test.tsx`에서 오버레이가 절대 배치와 함께 부모 패딩을 상속하는 계약을 검증한다.
- 기존 코드에서 새 테스트가 실패하는 것을 확인한 뒤 최소 변경을 적용한다.
- 집중 테스트를 통과시킨 후 별도 실행 앱에서 이미지와 텍스트가 함께 있는 일반 블릿을 포커스·선택하며 위치가 고정되는지 확인한다.

## 영향 범위

- 변경: React 인라인 스타일과 해당 컴포넌트 테스트
- 변경하지 않음: IPC, Rust, SQLite, 파일 저장, Undo/Redo, 이미지 데이터 모델, 키보드 명령, 첨부파일 크기·배치
