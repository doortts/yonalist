# Notes 설명 커서 및 Shift+Enter 이동·생성 설계

**작성일:** 2026-07-20

## 목표

서브 페이지와 일반 블릿의 설명을 편집할 때 커서를 표시 글자의 줄에 맞추고,
`Shift+Enter`로 다음에 보이는 블릿 제목으로 연속해서 이동할 수 있게 한다.
다음 블릿이 없으면 새 블릿을 만들고 그 제목에 커서를 둔다.

## 완료 조건

| 상황 | 기대 결과 |
| --- | --- |
| 서브 페이지 설명을 편집한다 | 기본 커서의 시작 위치가 14px 글자의 표시 줄보다 위에 떠 보이지 않는다. |
| 일반 블릿 설명을 편집한다 | 서브 페이지 설명과 같은 커서 보정이 적용된다. |
| 설명에서 `Enter`를 누른다 | 현재 설명 안에 줄바꿈이 입력된다. |
| 설명에서 `Shift+Enter`를 누르고 다음에 보이는 블릿이 있다 | 설명의 최신 값이 저장되고 다음 블릿 제목으로 포커스가 이동한다. |
| 마지막 일반 블릿 설명에서 `Shift+Enter`를 누른다 | 같은 깊이에 빈 다음 블릿이 만들어지고 새 제목에 커서가 놓인다. |
| 하위 블릿이 없는 서브 페이지 설명에서 `Shift+Enter`를 누른다 | 첫 하위 블릿이 만들어지고 새 제목에 커서가 놓인다. |
| 한글 등 IME 조합 중 `Shift+Enter`를 누른다 | 구조 명령을 실행하지 않고 입력기 동작을 유지한다. |
| `Shift+Enter` 키 반복 이벤트가 발생한다 | 한 번의 입력으로 블릿을 여러 개 만들지 않는다. |

## 원인

`NoteTextField`의 고정 표시 모드는 편집 중에도 `NoteTokenText` 표시층으로
글자를 그리고, 투명한 textarea에서는 브라우저 기본 커서만 보이게 한다.
표시층과 textarea의 바깥 상자는 이미 일치하지만, 설명은 `font-size: 14px`와
`line-height: 20px`를 사용한다. 브라우저 기본 커서는 20px 줄 상자를 기준으로
그려지고 표시 글자는 그 안에서 배치되므로, 커서 시작점이 글자보다 위에 떠
보인다. 이전의 `transform: none` 수정은 바깥 상자만 맞췄기 때문에 이 내부
기준선 차이는 해결하지 못했다.

설명 키 처리기는 현재 `Escape`, 경계의 `ArrowUp`, `ArrowDown`만 해석한다.
수정자 키가 있는 입력은 모두 브라우저에 넘기므로 `Enter`와 `Shift+Enter`가
동일한 줄바꿈으로 처리된다. 다만 다음에 보이는 노드를 계산하는
`supportingNoteFocusTarget`, 페이지의 첫 하위 생성 명령, 일반 블릿의 다음
형제 생성 명령은 이미 존재한다.

## 접근 비교

1. **설명 필드의 기본 커서층만 아래로 보정하고 기존 탐색·생성 명령을
   재사용한다 — 채택.** 표시 글자와 자동 높이 계산은 건드리지 않으며 페이지와
   일반 블릿에 같은 이동 규칙을 적용할 수 있다.
2. textarea의 줄 높이를 글자 크기와 같은 14px로 줄인다. 여러 줄에서 표시층은
   20px씩 이동하고 커서는 14px씩 이동해 두 층이 다시 어긋나므로 제외한다.
3. 기본 커서를 숨기고 별도 커서를 그린다. selection, 줄바꿈, IME와 접근성까지
   다시 구현해야 하므로 현재 문제에 비해 복잡하고 위험해 제외한다.

## 설계

### 1. 설명 커서층 보정

- 고정 표시 textarea 규칙은 `--notes-stable-caret-offset` 변수를 사용해
  `translateY`를 적용한다. 기본값은 `0`으로 두어 페이지 제목과 일반 블릿
  제목의 현재 정렬을 유지한다.
- `.notes-page-note-field`와 `.notes-node-note-field`에만 14px 글자와 20px
  줄 높이 차이의 절반인 `3px` 보정을 지정한다.
- 표시층의 글자 크기, 줄 높이, margin, textarea 자동 높이 및 포인터 위치 계산은
  변경하지 않는다. 여러 줄에서도 표시층과 편집층의 20px 행 간격은 동일하다.

### 2. 설명 전용 Shift+Enter 해석

- 설명 키 해석 결과에 `nextTitleOrCreate`를 추가한다.
- 수정자 키가 `Shift` 하나뿐인 비조합·비반복 `Enter`를
  `nextTitleOrCreate`로 해석한다.
- 일반 `Enter`는 해석하지 않아 textarea의 기본 줄바꿈을 유지한다.
- 기존 `Escape`, `ArrowUp`, `ArrowDown` 규칙과 수정자 화살표 동작은 유지한다.
- IME 조합 및 키 반복 이벤트에서는 새 구조 명령을 만들지 않는다.

### 3. 다음 블릿 이동과 마지막 블릿 생성

- 현재 보이는 노드 목록에서 현재 노드 다음 ID가 있으면, 작성 중인 설명의
  최신 값을 draft에 반영하고 기존 저장 경로로 flush한 뒤 그 제목에 포커스를
  둔다. 펼쳐진 하위 블릿이 바로 다음에 보이면 그 하위 블릿이 대상이다.
- 다음 ID가 없고 현재 편집기가 서브 페이지 설명이면 기존
  `createChild(nodeId, "first")`를 실행한다. 하위 블릿이 없으므로 이 항목은
  동시에 첫 번째이자 마지막 하위 항목이 된다.
- 다음 ID가 없고 현재 편집기가 일반 블릿 설명이면 기존
  `createNextTextSibling(nodeId)`를 실행해 같은 부모 아래 현재 블릿 다음에 빈
  텍스트 블릿을 만든다.
- 두 생성 명령은 이미 새 노드의 제목을 pending focus로 지정한다. 별도의 DOM
  포커스 조작은 추가하지 않는다.
- 구조 명령을 호출하기 전에 최신 설명을 동기적으로 draft에 반영한다. 기존
  structural draft barrier가 이 draft 저장을 완료하지 못하면 생성 명령을
  건너뛰므로, 저장되지 않은 설명 위에 구조 변경이 커밋되지 않는다.

## 데이터 및 Undo/Redo

- 설명 입력은 기존 텍스트 history 흐름을 유지한다.
- 새 블릿 생성은 기존 `createChild` 또는 `createNextTextSibling` 구조 history를
  사용하므로 Undo/Redo에 새로운 항목 형식을 추가하지 않는다.
- 저장 스키마, IPC, Rust, SQLite, filesystem 및 native configuration은
  변경하지 않는다.

## 테스트 전략

구현 전에 다음 회귀 테스트를 RED로 확인하고 한 행씩 GREEN으로 만든다.

1. 키 해석 단위 테스트에서 일반 `Enter`는 native로 남고, 비조합·비반복
   `Shift+Enter`만 `nextTitleOrCreate`가 되는지 검증한다.
2. 페이지 설명에서 다음 하위 블릿이 있으면 최신 설명을 저장하고 그 제목으로
   이동하며, 하위 블릿이 없으면 첫 하위 블릿을 만드는지 검증한다.
3. 일반 블릿 설명에서 다음에 보이는 블릿이 있으면 이동하고, 마지막이면 같은
   깊이의 다음 텍스트 블릿을 만드는지 검증한다.
4. 스타일 계약 테스트로 설명 필드만 3px 커서 보정을 받고 제목 필드는 기본값
   0을 유지하는지 검증한다.

프런트엔드 변경이므로 최종 게이트는 `npm test`, `npm run lint`,
`npm run build`, `git diff --check`다. Cargo 테스트, Rust formatting, Clippy는
Rust, IPC, persistence 또는 native configuration을 변경하지 않으므로 생략한다.

## 비대상

- 제목의 `Enter`, `Shift+Enter`, 분할 또는 하위 생성 동작 변경
- `ArrowUp`, `ArrowDown`, `Escape` 설명 탐색 규칙 변경
- 블릿 들여쓰기, 정렬, 접기 상태 또는 설명 간격 변경
- 설명 글자 크기, 줄 높이, 색상 및 포커스 표시 변경
- custom caret 구현 또는 브라우저 selection 동작 변경

## 직접 확인

새로 빌드한 별도 Tauri 앱에서 다음 경로를 확인한다.

1. 서브 페이지 설명의 처음, 중간, 끝과 두 번째 줄에 커서를 놓아 표시 글자와
   같은 줄에 보이는지 확인한다.
2. 설명에서 `Enter`를 눌러 줄바꿈이 유지되는지 확인한다.
3. 다음 블릿이 있는 설명에서 `Shift+Enter`를 눌러 다음 제목으로 이동하는지
   확인한다.
4. 마지막 일반 블릿 설명에서 `Shift+Enter`를 눌러 같은 깊이의 빈 블릿이
   만들어지고 바로 입력할 수 있는지 확인한다.
5. 하위 블릿이 없는 서브 페이지 설명에서 `Shift+Enter`를 눌러 첫 하위 블릿이
   만들어지는지 확인한다.
