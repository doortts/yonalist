# Notes To-do 블릿과 직계 진행률 설계

## 계약

| 항목 | 내용 |
| --- | --- |
| 목표 | 일반 블릿을 명시적인 To-do 체크박스 블릿으로 전환하고, 부모에서 직계 자식 To-do의 완료도를 한눈에 확인한다. 완전히 빈 일반 블릿은 편집 전까지 시각적 잡음을 만들지 않는다. |
| 완료 조건 | 블릿 메뉴와 제목 시작점의 `/` 메뉴에서 To-do로 전환할 수 있다. To-do에서 Enter로 만든 다음 동일 레벨 항목은 미완료 To-do다. 체크 상태는 저장·동기화·Undo/Redo된다. 부모의 제목/노트 아래에는 직계 자식 To-do만 집계한 진행 막대와 `(완료/전체)`가 표시된다. 진행 중 막대는 붉은색이고 전부 완료되면 녹색이다. 완전히 빈 일반 블릿은 포커스 전까지 점을 숨긴다. |
| 비대상 | 재귀 하위 To-do 집계, 마감일·우선순위·담당자, 자동 생성 설명 문구, 사이드바/검색 결과 진행률, 구형 SQLite 마이그레이션은 포함하지 않는다. |
| 경계 | React 아웃라인·페이지 제목·메뉴·슬래시 명령, Notes 명령과 Undo/Redo, TypeScript/Rust IPC 모델, SQLite 스키마·저장소, Markdown topic/trash 동기화 형식이 바뀐다. |
| 데이터·Undo/Redo | 노드에 `markerKind: "bullet" | "todo"`를 영속화한다. 완료 여부는 기존 `completedAt`을 사용한다. 타입 전환, 체크 변경, 슬래시 명령 적용은 각각 하나의 원자적 기록으로 Undo/Redo한다. |
| 직접 확인 | 격리된 임시 vault의 새 데스크톱 앱에서 일반 블릿을 메뉴와 `/todo`로 전환하고, Enter 상속, 체크/진행률 색상, 빈 블릿 표시, Undo/Redo, 재시작과 파일 동기화 왕복을 확인한다. |

## 선택한 접근

노드의 콘텐츠 형식인 `nodeKind` 및 자식 배치 방식인 `layoutMode`와 별개로
`markerKind`를 추가한다. `markerKind`는 해당 행 자체가 일반 블릿인지 To-do인지
나타내는 의미 필드다. 이 구분은 체크되지 않은 To-do도 일반 블릿과 명확히 구별하며,
향후 보드 같은 자식 레이아웃과 충돌하지 않는다.

검토했지만 선택하지 않은 접근은 다음과 같다.

- `layoutMode`에 To-do를 넣으면 현재 행의 마커와 자식 레이아웃이라는 서로 다른
  의미가 한 필드에 섞인다.
- `completedAt`만으로 추론하면 미완료 To-do와 일반 블릿을 구별할 수 없다.
- 제목 접두사나 체크박스 문자를 저장하면 사용자의 텍스트와 구조 데이터가 섞이고
  편집·검색·동기화가 취약해진다.

## 데이터 모델과 저장

- TypeScript와 Rust의 모든 `NoteNode` 표현에 `markerKind`를 추가한다.
- 허용 값은 `bullet`과 `todo`뿐이며 새 노드의 기본값은 `bullet`이다.
- SQLite `notes_nodes`에는 `marker_kind TEXT NOT NULL DEFAULT 'bullet'`을 추가하고
  허용 값 제약을 둔다.
- Notes SQLite 스키마 버전을 2에서 3으로 올린다. 개발 단계 방침에 따라 구형
  SQLite를 자동 변환하지 않으며 기존 초기화 기능으로 새 스키마를 만든다.
- 저장소의 생성·조회·수정·복제·이동·휴지통 복원·히스토리 재생 및 서브트리
  가져오기/내보내기는 값을 빠뜨리지 않고 보존한다.
- 텍스트와 이미지 노드 모두 행 마커 속성을 가질 수 있다. 이미지가 포함된 To-do도
  동일한 체크·진행률·이동 규칙을 사용한다.

## Markdown 동기화

topic/trash 형식 버전을 2에서 3으로 올리고 일반 노드 메타데이터 주석에 `todo`
토큰을 추가한다. topic 루트에는 `root_marker_kind: bullet | todo` frontmatter를
추가한다. 버전이 올라가기 전 파일, `todo` 토큰이 없는 노드,
`root_marker_kind`가 없는 루트는 일반 블릿으로 읽는다. 따라서 기존의 미완료
`[ ]` 줄이 새 앱에서 전부 To-do로 바뀌지 않는다.

새 형식의 기본 렌더링은 다음과 같다.

- 미완료 일반 블릿: `- 제목`
- 완료된 일반 블릿: `- [x] 제목`, `todo` 토큰 없음
- 미완료 To-do: `- [ ] 제목`, 메타데이터 주석에 `todo`
- 완료된 To-do: `- [x] 제목`, 메타데이터 주석에 `todo`

파서는 `todo` 토큰의 중복과 잘못된 위치를 기존 메타데이터 검증 규칙으로 거부한다.
동기화 병합은 `markerKind`를 다른 노드 필드와 함께 HLC 승자 값으로 적용한다. 새
형식을 모르는 구버전 앱이 의미를 조용히 제거하지 않도록 상위 형식 버전 파일은 기존
규칙대로 격리한다.

## 생성과 편집 동작

### 블릿 메뉴

- 현재 영문 UI에 맞춰 일반 블릿에는 `To-do`, To-do에는 `Change to bullet`을
  표시한다.
- 전환은 제목, 노트, 첨부파일, 자식, 별표와 현재 `completedAt`을 보존한다. 따라서
  일반 블릿의 기존 완료 상태도 전환 과정에서 손실되지 않는다.
- 기존 완료/미완료 메뉴와 단축키는 유지하고, To-do에서는 체크박스와 같은
  `completedAt`을 조작한다.

### 슬래시 명령

제목 시작점에서 `/`를 입력해 여는 메뉴에 `To-do`를 추가한다. 선택하면 명령어로
인식된 텍스트만 제거하고 나머지 제목과 커서 위치를 보존한 채 `markerKind`를
`todo`로 바꾼다. 텍스트 수정과 타입 변경은 하나의 저장 명령이므로 한 번의 Undo로
함께 돌아간다. 이미지 중심 행은 제목 편집 영역에서 같은 명령을 사용할 수 있다.

### Enter 상속

To-do 제목에서 Enter로 분할하거나 다음 동일 레벨 행을 만들면 새 행의
`markerKind`도 `todo`이고 `completedAt`은 항상 `null`이다. 기존 행의 완료 상태는
유지한다. 제목 노트에서 다음 형제로 이동하면서 마지막에 새 행을 만드는 기존
Shift+Enter 경로도 같은 생성 규칙을 공유하여 서로 다른 종류의 새 항목이 생기지
않게 한다.

## 행 레이아웃

일반 행은 기존 열 구조와 제목 위치를 유지한다. 제목, 노트, 이미지, 자식이 모두
없는 완전히 빈 일반 블릿은 점의 공간은 유지하되 점만 숨긴다. 그 행의 제목 편집기가
포커스를 얻으면 점을 표시한다. 단순 호버만으로는 빈 점을 표시하지 않으며, To-do의
체크박스는 제목이 비어 있어도 항상 보인다.

To-do 행은 `메뉴 | 펼침 표시 | 서브 페이지 진입 점 | 체크박스 | 제목` 순서의 고정
열을 사용한다.

- 평상시에는 체크박스만 마커로 보인다.
- 행을 호버하거나 행 내부에 포커스가 있으면 메뉴와 서브 페이지 진입 점도
  체크박스 앞에 나타난다.
- 숨겨진 컨트롤의 열 너비는 유지하여 호버·포커스 전환 때 체크박스와 제목이
  움직이지 않게 한다.
- 자식 펼침 표시는 자식이 있는 행에서 기존 규칙대로 동작한다.
- To-do를 서브 페이지로 열었을 때는 페이지 제목 앞에도 체크박스를 보여 현재
  항목의 종류와 완료 상태를 유지한다. 현재 페이지이므로 별도의 진입 점은 표시하지
  않는다.
- 체크박스는 키보드 접근과 `aria-checked`를 지원하고, 체크 여부를 색상만으로
  전달하지 않는다.

## 직계 자식 진행률

각 부모 노드에 대해 정규화된 작업공간에서 `parentId`가 정확히 부모 ID와 같은
자식만 확인한다. 그중 `markerKind === "todo"`인 항목의 수가 전체이며,
`completedAt !== null`인 항목의 수가 완료다. 손자 이하의 To-do는 집계하지 않는다.

- 직계 To-do가 없으면 진행률을 렌더링하지 않는다.
- 직계 To-do가 있으면 짧은 막대와 `(완료/전체)`를 표시한다.
- 일부만 완료된 막대의 채움은 붉은색이다.
- `완료 === 전체`이면 채움을 100%로 만들고 녹색으로 바꾼다.
- 0개 완료 상태는 채움이 0이지만 `(0/전체)` 숫자로 상태를 전달한다.
- 사용자가 적은 노트가 있으면 그 아래에, 노트가 없으면 제목 바로 아래에 표시한다.
- `직계 작업의 완료 상태` 같은 설명 문구나 노트 텍스트는 자동으로 만들지 않는다.
- 아웃라인 행과 현재 서브 페이지 제목은 같은 파생 계산을 사용한다.

진행률은 저장 필드가 아니라 현재 자식 상태에서 계산하는 표시 값이다. 체크,
종류 전환, 이동, 삭제, 복원 또는 Undo/Redo 후 작업공간이 갱신되면 즉시 다시
계산한다.

## 실패와 일관성 처리

- 종류 전환과 슬래시 명령은 저장소에서 원자적으로 적용한다. 일부만 적용된 UI를
  성공 상태로 남기지 않는다.
- IPC·저장 실패는 기존 Notes 오류 경로로 전달하고 마지막 확정 작업공간을 유지한다.
- 잘못된 `markerKind`나 동기화 메타데이터는 조용히 일반 블릿으로 보정하지 않고
  기존 유효성 검사·격리 정책을 따른다.
- 진행률 계산은 저장 작업을 만들지 않으므로 렌더링 자체가 동기화나 히스토리를
  발생시키지 않는다.

## 검증

### 순수 모델과 프런트엔드

- 누락된 새 필드의 기본값, 유효 값 검증, IPC 직렬화 형태를 확인한다.
- 빈 일반 블릿의 점은 비포커스에서 숨고 포커스에서만 나타나는지 확인한다.
- To-do의 평상시·호버·포커스 상태에서 컨트롤 가시성은 바뀌지만 제목 좌표는
  변하지 않는지 확인한다.
- 메뉴 전환과 `/todo`가 타입을 바꾸고 나머지 제목을 보존하는지 확인한다.
- Enter 및 마지막 노트의 Shift+Enter가 미완료 To-do 형제를 만드는지 확인한다.
- 직계 자식만 집계하고, 일부 완료는 붉은색, 전부 완료는 녹색이며, 자동 설명 문구가
  생기지 않는지 확인한다.

### Rust·SQLite·동기화

- 현재 스키마가 새 필드를 저장하고 구형 DB를 마이그레이션하지 않는지 확인한다.
- 생성·전환·체크·복제·이동·삭제·복원과 Undo/Redo가 값을 보존하는지 확인한다.
- topic/trash 버전, 루트의 `root_marker_kind`, 일반 노드의 `todo` 토큰,
  일반/완료/To-do 줄을 렌더링-파싱-재렌더링해 동일한 의미가 유지되는지 확인한다.
- 이전 형식 파일은 모든 기존 노드를 일반 블릿으로 읽고, 새 형식 파일은 구버전
  형식 지원 범위를 넘어설 때 격리되는지 확인한다.
- 동기화 병합 후 종류와 완료 상태가 함께 올바른 승자 값을 갖는지 확인한다.

### 데스크톱

격리한 임시 vault와 새 SQLite에서 앱을 새로 빌드·재시작한다. 메뉴와 `/todo` 전환,
Enter 상속, 체크와 부모 진행률, 빈 블릿, 서브 페이지 제목, Undo/Redo를 한 번씩
확인한다. 앱을 재시작하고 Markdown 파일 왕복 뒤 상태가 유지되는지 확인한다. 이후
관련 집중 테스트와 owning suite를 실행하고, 변경 경계가 저장소와 Rust를 포함하므로
프런트엔드 테스트·린트·빌드, Rust 테스트·포맷, `git diff --check`를 최종 한 번
실행한다.
