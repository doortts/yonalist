# Yonalist 통합 탐색 패널 설계

## 상태

- 작성일: 2026-07-27
- 상태: 승인됨
- 선택안: 기능별 구역형 탐색 패널

## 판단

기존 첫 패널은 Yonalist와 Settings 전환만 담당하지만 240px을 차지한다. 두 번째
패널은 Notes의 탐색 기능과 페이지 목록을 모두 담아 340px을 더 차지한다. Notes가
제품의 중심이 된 현재 구조에서는 이 구분이 사용자에게 별다른 정보를 주지 않는다.

두 패널을 합치면 기본 너비 기준으로 편집 영역을 약 240px 넓힐 수 있다. 다만
기존 첫 패널의 폭은 페이지 제목과 검색 결과를 담기에 좁으므로 통합 패널의 기본
너비를 336px로 정한다.

Settings는 예외로 둔다. 설정 카테고리와 세부 항목은 서로 다른 탐색 단계이므로
Settings를 여는 동안만 세 번째 패널을 사용한다. 설정은 일시적으로 여는 화면이라
편집 공간이 줄어들어도 Notes 작업을 방해하지 않는다. 현재
`SettingsCategoryPane`과 `SettingsPage`의 역할도 그대로 유지할 수 있다.

## 화면 구조

### Yonalist: 2단 패널

```text
┌────────────────────────────────┬──────────────────────────────────────┐
│ Yonalist                       │ 현재 Notes 세부 화면                 │
│ [New page]                     │                                      │
│ [Search Yonalist]              │                                      │
│                                │                                      │
│ LIBRARY                        │                                      │
│ All                            │                                      │
│ Starred                        │                                      │
│ Recent                         │                                      │
│ Tags                           │                                      │
│ Archive                        │                                      │
│ Trash                          │                                      │
│                                │                                      │
│ PAGES                          │                                      │
│ Yonalist 시작하기              │                                      │
│ GitHub Notifications           │                                      │
│                                │                                      │
│ Settings                       │                                      │
└────────────────────────────────┴──────────────────────────────────────┘
```

통합 탐색 패널의 순서는 다음과 같다.

1. Yonalist 제목과 데이터 설정, 로그인 필요, 오프라인 상태 동작
2. `New page`
3. `Search Yonalist`
4. `Library`: All, Starred, Recent, Tags, Archive, Trash
5. 활성 태그, 검색 결과 또는 태그 목록
6. `Pages`: 현재 보기에서 표시할 루트 페이지와 GitHub Notifications
7. 아래쪽에 고정된 `Settings`

`Library`에서 선택한 보기와 현재 페이지는 동시에 활성 상태가 될 수 있다. 보기
선택은 옅은 배경으로, 현재 페이지는 더 강한 선택 배경과 왼쪽 표시선으로 구분한다.
검색 중에는 기존처럼 검색 결과를 보여 주고 페이지 목록의 동작은 바꾸지 않는다.

Yonalist 제목과 Settings는 패널 위아래에 고정한다. 그 사이의 새 페이지, 검색,
Library 보기, 검색·태그 결과와 Pages를 하나의 영역으로 스크롤한다. 중첩된
스크롤 영역은 만들지 않는다.

### Settings: 3단 패널

```text
┌──────────────────────┬──────────────────────┬──────────────────────────┐
│ 통합 Yonalist 탐색   │ 설정 카테고리        │ 선택한 설정 세부 항목    │
│                      │ Appearance           │                          │
│                      │ GitHub 서버          │                          │
│                      │ Vault and sync       │                          │
│                      │ Yonalist             │                          │
│                      │ Plugins              │                          │
│ Settings [선택]      │ Reset                │                          │
└──────────────────────┴──────────────────────┴──────────────────────────┘
```

Settings를 누르면 첫 패널은 그대로 두고 Settings만 선택 상태로 바꾼다. 두 번째
패널에는 기존 `SettingsCategoryPane`, 세 번째 패널에는 기존 `SettingsPage`를
표시한다.

Settings가 열린 상태에서 첫 패널의 Library 보기, 페이지, 새 페이지 또는 검색
결과를 선택하면 Settings를 닫고 요청한 Notes 동작을 실행한다. 설정 세부 화면의
닫기 버튼은 이전 Notes 화면으로 돌아간다. Notes 기능은 Settings가 열린 동안에도
마운트된 상태를 유지한다. 이전 Library 보기와 페이지 상태는 보존하지만
Settings가 선택된 동안에는 Settings 행만 강한 선택 표시를 쓴다. Notes로
돌아오면 기존 보기와 페이지의 선택 표시를 복원한다.

## 컴포넌트와 책임

### 통합 Yonalist 탐색 패널

기존 `Sidebar`와 `NotesLibraryPane`의 화면 책임을 하나의
`YonalistNavigationPane`으로 합친다.

- 앱 수준 책임: 온라인 전환, 로그인 필요 표시, Settings 열기
- Notes 책임: 새 페이지, 검색, 라이브러리 보기, 태그, 페이지 목록, 페이지 메뉴,
  내보내기 상태, GitHub Notifications 열기
- 표시 책임: 한 개의 패널 테두리, 한 개의 제목, 패널 내부 스크롤과 고정 영역

Notes 저장소나 명령 코드는 옮기지 않는다. `NotesLibraryPane` 안의 동작을 탐색
패널 내용으로 추출하고 기존 Context와 action을 그대로 사용한다. 앱 셸은 이
컴포넌트를 Notes 기능 Provider 안에 한 번만 마운트한다. Settings로 전환해도
컴포넌트를 다시 만들지 않는다.

Notes 중심 제품이라는 현재 방향에 맞춰 통합 탐색 패널을 앱 셸의 고정 영역으로
둔다. 앞으로 외부 소스나 플러그인이 추가되면 `Pages`에 나타나며, 새 전역 기능
레지스트리를 미리 만들지는 않는다.

### 기능별 가운데 패널

`FeaturePanes.middle`은 선택 사항으로 바꾼다.

- Notes: 가운데 패널 없음
- Settings: `SettingsCategoryPane`
- Settings 로딩·오류: 가운데 패널 자리에 기존 로딩 또는 재시도 화면

앱 셸은 현재 기능이 가운데 패널을 제공하는지 `data` 속성으로 표시한다. CSS는
이 값으로 Notes의 가운데 열과 두 번째 리사이저를 제거한다. 숨긴 0px 패널을
남겨 자동 배치에 의존하지 않는다.

### 세부 패널

Notes의 `NotesDetailSplitHost`와 Settings의 `SettingsPage`는 기존 기능별
세부 패널 자리를 공유한다. Notes의 분할 편집 세션과 초안 상태는 기존
`keepMounted` 계약을 따른다.

## 상태와 패널 너비

- 통합 탐색 패널 기본 너비: 336px
- 통합 탐색 패널 허용 범위: 320px–480px
- Settings 카테고리 패널: 기존 `list` 너비와 리사이저 사용
- Notes에서는 `list` 너비와 접힘 상태를 레이아웃에 적용하지 않음
- Settings에서만 `list` 너비를 적용

기존 `yonalist.paneWidths.v1`의 `sidebar` 값을 통합 탐색 패널 너비로 계속 쓴다.
저장값이 기존 최소 폭보다 작으면 새 최소 폭인 320px로 보정한다. 새 저장 형식,
호환 판독기, 마이그레이션은 추가하지 않는다.

첫 패널 접기 버튼은 통합 탐색 패널 전체를 접는다. Notes 세부 화면 최대화는
통합 탐색 패널을 숨긴다. Settings 세부 화면 최대화는 통합 탐색 패널과 설정
카테고리 패널을 함께 숨긴다.

## 전환 흐름

### Settings 열기

1. 기존 기능 전환 경로로 활성 기능을 Settings로 바꾼다.
2. 통합 탐색 패널은 그대로 두고 Settings 행만 선택 표시한다.
3. 설정 카테고리 패널을 열고 마지막으로 선택한 설정 카테고리를 표시한다.
4. 설정 세부 화면을 세 번째 패널에 표시한다.

Settings를 연다는 이유로 Notes 초안을 새로 저장하거나 비우는 동작은 추가하지
않는다. Notes Provider와 초안 저장 계약을 그대로 따른다.

### Notes로 돌아가기

1. 설정 세부 화면의 닫기 버튼이나 통합 탐색 패널의 Notes 항목을 사용한다.
2. 설정 카테고리 패널을 제거한다.
3. 이전 Notes 세부 화면을 다시 표시한다.
4. 사용자가 Notes 항목을 선택해서 돌아왔다면 해당 명령을 이어서 실행한다.

Settings 전환 중 Notes Provider와 편집 세션은 유지한다. 현재 페이지, 초안,
탐색 보기, 검색어와 분할 패널 등록 정보가 Settings 전환 때문에 초기화되면 안
된다. DOM 포커스 복원 방식은 이번 작업에서 새로 바꾸지 않는다.

## 준비·오류 상태

Notes 런타임이 아직 준비되지 않았으면 통합 탐색 패널에는 제목, 연결 상태와
Settings만 표시하고 Notes 탐색 동작은 로딩 상태로 둔다. Notes 런타임을 열지
못해도 사용자는 Settings에 들어갈 수 있어야 한다.

설정 런타임을 열지 못하면 통합 탐색 패널은 유지하고 세부 영역에 기존 재시도
화면을 표시한다. 실패한 설정 카테고리 패널 때문에 Notes 탐색 패널까지
사라지지 않는다.

새 네트워크 호출이나 저장 작업은 추가하지 않는다. 검색, 내보내기, 데이터 삭제
오류는 현재 `NotesLibraryPane`의 표시와 대화상자를 그대로 사용한다.

## 반응형 배치

### 981px 이상

- Yonalist: 통합 탐색 패널과 Notes 세부 화면을 가로로 배치
- Settings: 통합 탐색 패널, 설정 카테고리, 설정 세부 화면을 가로로 배치

### 721px–980px

- Yonalist: 통합 탐색 패널과 Notes 세부 화면을 가로로 배치
- Settings: 통합 탐색 패널은 왼쪽 전체 높이를 사용하고, 오른쪽에서 설정
  카테고리와 세부 화면을 위아래로 배치

### 720px 이하

- 통합 탐색 패널, 선택적인 설정 카테고리, 세부 화면을 세로로 쌓는다.
- 패널 리사이저와 데스크톱 접기 버튼은 표시하지 않는다.

## 접근성

- 통합 패널은 `Navigation` landmark 하나만 제공한다.
- Library 보기에는 기존 `aria-pressed`, 검색 결과에는 기존 listbox 계약을
  유지한다.
- 현재 페이지와 Settings의 선택 상태를 각각 보조 기술에 전달한다.
- Settings가 열릴 때 설정 카테고리 탭으로 초점을 강제로 옮기지 않는다.
  사용자가 Settings를 연 버튼에서 자연스럽게 다음 요소로 이동할 수 있게 한다.
- 가운데 패널이 없는 Notes 화면에서는 숨은 리사이저와 초점을 받을 수 있는
  빈 요소를 남기지 않는다.

## 검증

### 컴포넌트 테스트

- 통합 탐색 패널에 모든 Library 보기와 루트 페이지, GitHub Notifications,
  Settings가 나타나는지 확인
- 검색, 태그, 페이지 메뉴, 새 페이지, 데이터 설정, 외부 페이지 동작이 기존
  action을 호출하는지 확인
- 보기 선택과 페이지 선택이 서로 다른 표시를 쓰는지 확인
- Settings가 열린 상태에서 Notes 항목을 선택하면 Settings를 닫고 요청한 동작을
  실행하는지 확인

### 앱 셸 테스트

- Notes 활성 상태에서 가운데 패널과 해당 리사이저를 렌더링하지 않는지 확인
- Settings 활성 상태에서 통합 탐색, 설정 카테고리, 설정 세부 화면이 모두
  렌더링되는지 확인
- Settings를 열고 닫아도 Notes Provider와 세부 패널이 재마운트되지 않는지 확인
- Notes 로딩이나 오류 상태에서도 Settings에 접근할 수 있는지 확인
- 패널 너비 보정, 리사이저, 접기, 세부 화면 최대화 동작 확인
- 데스크톱과 두 반응형 구간의 패널 배치 계약 확인

### 직접 확인

새로 빌드한 macOS 앱과 별도 Vault에서 다음 순서로 확인한다.

1. Yonalist가 2단 패널로 열리고 빈 가운데 열이나 리사이저가 없는지 확인
2. 페이지 제목이 긴 경우 말줄임과 페이지 메뉴가 정상인지 확인
3. 검색, Tags, Archive, Trash, GitHub Notifications를 차례로 열어 확인
4. Settings를 열었을 때 3단 패널이 되는지 확인
5. 설정 카테고리를 바꾸고 Settings를 닫아 이전 Notes 페이지와 초안이 남는지 확인
6. Settings가 열린 상태에서 Notes 페이지를 눌러 바로 돌아오는지 확인
7. 첫 패널 접기, 세부 화면 최대화, 창 너비 변경 후 배치를 확인

## 구현 시 주의할 점

- 현재 작업 트리의 GitHub Notifications 시작 시점 수정과 겹치지 않게 파일별
  변경 범위를 확인한다.
- `NotesLibraryPane`의 동작 코드를 복제하지 않고 통합 탐색 컴포넌트로 옮긴다.
- Notes의 Provider 생명주기와 기능 패널 메모이제이션을 유지한다.
- 설정을 위해 범용 패널 프레임워크나 새 탐색 레지스트리를 만들지 않는다.
