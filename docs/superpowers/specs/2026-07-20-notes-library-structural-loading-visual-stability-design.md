# Notes 라이브러리 구조 변경 시각 안정성 설계

**작성일:** 2026-07-20

## 계약

| 구분 | 내용 |
| --- | --- |
| 목표 | 오른쪽 작성 pane에서 유효한 `Tab`/`Shift+Tab` 구조 이동을 실행해도 왼쪽 Notes 라이브러리 pane의 밝기와 표시가 깜박이지 않는다. |
| 완료 조건 | 구조 이동이 진행 중인 동안 `New page`와 페이지 행/메뉴가 기존 밝기를 유지하고, 작업 완료 후에도 같은 표시를 유지한다. |
| 안전 조건 | 진행 중인 구조 변경과 경쟁하는 왼쪽 명령은 기존처럼 비활성화한다. |
| 유지 조건 | 최초 workspace 로딩, 데이터 삭제, 오류, 빈 상태의 기존 표시와 비활성화 동작은 유지한다. |
| 비대상 | 구조 명령 큐, 저장, Undo/Redo, 포커스, 들여쓰기 규칙, IPC, Rust, SQLite 스키마 변경은 하지 않는다. |
| 경계 | React 표시와 Notes CSS만 변경하는 프런트엔드 변경이다. |
| 직접 확인 | 격리된 새 Tauri 앱에서 여러 차례 Tab/Shift+Tab을 실행해 왼쪽 pane이 밝아지거나 어두워지지 않는지 확인하고, 구조 이동과 명령 차단이 유지되는지 확인한다. |

## 원인

`moveNode`는 구조 명령 큐에 들어가며, 큐가 작업을 시작하면 workspace가 잠시
`loading` 상태가 된다. Notes 라이브러리는 이 상태를 구독하고 `New page`와
페이지 행/메뉴를 `disabled`로 전환한다. 전역 `.primary-button:disabled` 규칙은
`New page`의 불투명도를 `0.55`로, 페이지 메뉴 규칙은 메뉴 아이콘의 불투명도를
`0.34`로 낮춘다. 명령이 빠르게 끝나면 이 값이 원래 밝기로 복구되어 pane 전체가
재렌더링되는 것처럼 보인다. DOM이 재마운트되는 문제는 아니다.

## 접근 비교

1. **구조 변경 중 비활성화 표시는 유지하되 밝기만 고정 — 채택.** 명령 직렬화와
   안전성은 그대로 두고 시각적 깜박임만 제거한다. 변경 범위도 라이브러리 표시와
   CSS로 제한된다.
2. `moveNode`를 loading을 만들지 않는 silent 구조 명령으로 처리한다. 연속 키
   입력이 아직 반영되지 않은 구조를 기준으로 중복 실행될 수 있고, 기존 busy
   소유권을 약화시키므로 제외한다.
3. 라이브러리 전용 context로 상태를 분리해 실제 React 렌더를 줄인다. 장기적인
   최적화 여지는 있지만 이번 시각 증상보다 변경 범위와 회귀 위험이 크다.

## 설계

- 루트 데이터가 이미 있고 workspace만 잠시 `loading`인 상태를
  `transientWorkspaceBusy`로 구분한다. 데이터 삭제 중에는 이 상태를 적용하지
  않는다.
- Notes 라이브러리 section에 이 상태를 나타내는 data attribute를 둔다.
- data attribute가 활성화된 동안에도 모든 기존 `disabled` 속성과 `aria-busy`는
  유지한다.
- CSS에서 `New page`, 페이지 버튼, 페이지 메뉴 트리거의 색상과 불투명도를
  ready 상태와 동일하게 고정한다.
- 최초 로딩처럼 root가 아직 없는 상태와 데이터 삭제 상태에는 안정화 규칙을
  적용하지 않는다.

## 검증

1. 실제 Notes workspace 통합 테스트에서 지연된 `moveNode`를 사용해 구조 명령이
   pending인 동안 왼쪽 컨트롤이 계속 비활성화되고 transient 표시가 활성화되는지
   검증한다.
2. CSS 계약 테스트에서 transient 표시 아래의 `New page`, 페이지 버튼, 페이지
   메뉴 트리거가 ready 상태 밝기를 유지하는지 검증한다.
3. 최초 로딩과 데이터 삭제 상태에는 transient 표시가 붙지 않는지 검증한다.
4. 소유 테스트를 통과시킨 뒤 기존 앱과 다른 product name, bundle identifier,
   포트와 임시 HOME/Vault를 사용하는 새 Tauri 프로세스에서 직접 확인한다.
5. 새 프로세스가 임시 Vault만 열었는지 확인하고 검증 후 새 스택과 임시 데이터만
   정리한다.
