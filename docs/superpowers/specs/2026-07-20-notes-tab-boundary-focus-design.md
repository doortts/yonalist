# Notes Tab 경계 포커스 유지 설계

**작성일:** 2026-07-20

## 목표

제목에서 `Tab` 또는 `Shift+Tab`을 눌렀지만 더 이상 들여쓰기나 내어쓰기를
할 수 없는 경우, 브라우저의 기본 Tab 이동을 막고 현재 제목에 포커스를
유지한다.

## 완료 조건

| 상황 | 기대 결과 |
| --- | --- |
| 첫 번째 형제 제목에서 `Tab` | 구조를 바꾸지 않고 현재 제목 포커스를 유지한다. |
| 루트 제목에서 `Shift+Tab` | 구조를 바꾸지 않고 현재 제목 포커스를 유지한다. |
| 줌 루트의 직접 하위 제목에서 `Shift+Tab` | 줌 범위를 벗어나지 않고 현재 제목 포커스를 유지한다. |
| 서브 페이지 제목에서 `Tab` 또는 `Shift+Tab` | 페이지를 이동하지 않고 현재 제목 포커스를 유지한다. |
| 구조 이동이 가능한 제목에서 `Tab` 또는 `Shift+Tab` | 기존과 같이 들여쓰기 또는 내어쓰기를 수행한다. |
| 설명 입력란이나 이미지 내부 컨트롤에서 `Tab` | 기존의 기본 포커스 이동을 유지한다. |

## 원인

`resolveOutlineKey`는 구조 이동이 불가능한 Tab 경계에서 `null`을 반환한다.
제목 키 핸들러는 `null`을 앱이 소유하지 않는 키로 해석해 `preventDefault()`를
호출하지 않는다. 따라서 브라우저가 기본 Tab 순서를 실행하면서 포커스가
사이드바나 다른 컨트롤로 이동한다.

서브 페이지 제목은 `resolveOutlineKey`가 반환한 구조 이동을 페이지 헤더가
허용하지 않는 경우에도 Tab 이벤트를 소비하지 않아 같은 문제가 발생한다.

## 접근 비교

1. **인식된 Tab no-op을 명시적인 resolution으로 반환 — 채택.** 키 해석기에서
   구조적 no-op과 미지원 키를 구분하므로 두 제목 렌더러가 같은 의미를
   공유하고, 유효한 이동 경로는 바뀌지 않는다.
2. 각 제목 컴포넌트가 `null`인 모든 Tab을 직접 막는다. 구현은 짧지만 수정자,
   IME, 이미지 컨트롤처럼 기본 동작을 유지해야 하는 경로까지 과도하게 막을
   위험이 있다.
3. 기본 Tab 이동 후 포커스를 되돌린다. 화면 깜빡임과 blur 저장을 유발하므로
   제외한다.

## 설계

- `OutlineKeyResolution`에 `consumeTabShortcut`을 추가한다.
- 수정자 없는 `Tab`/`Shift+Tab`이 반복 이벤트이거나 구조 경계에 닿으면 이
  resolution을 반환한다.
- 줌 루트 자체는 페이지 헤더에서 구조 이동할 수 없으므로 Tab/Shift+Tab을
  `consumeTabShortcut`으로 해석한다.
- 일반 행과 페이지 헤더는 resolution을 받는 즉시 `preventDefault()`를 호출하고
  `consumeTabShortcut`에서는 다른 명령 없이 반환한다.
- Alt/Ctrl/Meta가 포함된 Tab, IME 조합, 설명 textarea, 이미지 내부의 native Tab
  소유권은 변경하지 않는다.
- 저장, Undo/Redo, IPC, Rust, SQLite 스키마는 변경하지 않는다.

## 테스트 및 직접 확인

1. 순수 키 해석 테스트로 첫 형제, 루트, 줌 경계, 반복 Tab이 consume 결과를
   내는지 확인한다.
2. 일반 행 통합 테스트로 `keydown`이 취소되고 포커스와 구조가 유지되는지
   확인한다.
3. 페이지 헤더 테스트로 서브 페이지 제목의 Tab/Shift+Tab이 취소되는지
   확인한다.
4. 기존 앱과 다른 product name, bundle identifier, 개발 포트를 사용해 새 Tauri
   프로세스를 띄운다. `mktemp -d /tmp/yonalist-tab-boundary.XXXXXX`로 만든 임시
   HOME을 전달해 기본 Vault가 임시 디렉터리 아래에 생성되도록 한다.
5. 새 프로세스가 별도 포트를 소유하고, 열린 `notes.sqlite`/WAL/SHM/lock 파일이
   모두 임시 HOME 아래에만 있는지 확인한 뒤 경계 Tab/Shift+Tab과 유효한 이동을
   직접 확인한다. 기존 앱 프로세스와 사용자 Vault는 건드리지 않는다.
6. 확인 후 새 개발 스택만 종료하고 임시 Vault와 캡처를 휴지통으로 옮긴다.

## 비대상

- 유효한 들여쓰기/내어쓰기 규칙 변경
- 여러 항목 선택의 Tab 명령 및 오류 메시지 변경
- 설명 입력란의 Tab 동작 변경
- 이미지 편집기 내부 포커스 순서 변경
