# Notes Multi-Image Ingest Design

## 목적

Notes 블릿 메뉴의 이미지 선택 오류를 해결하고, 이미지 파일을 파일 선택기, 드래그 앤 드롭, 클립보드 붙여넣기로 안정적으로 추가한다. 여러 이미지가 한 번에 들어오면 입력 순서를 유지한 채 모두 저장하며, 전체 작업은 하나의 원자적 저장 및 `Undo` 단위로 처리한다.

## 현재 문제와 원인

- Tauri capability에 `dialog:allow-open`이 없어 `Upload image`가 파일 선택기를 열지 못한다.
- 브라우저 DOM `drop` 이벤트와 `File.path`에 의존하는 현재 구현은 Tauri의 네이티브 파일 드롭 경로를 받지 못한다.
- 현재 드롭 처리기는 이미지가 정확히 한 개일 때만 허용한다.
- 클립보드 이미지에는 안정적으로 사용할 수 있는 운영체제 파일 경로가 없으므로 현재 경로 기반 import 명령을 재사용할 수 없다.
- 드롭 중 어느 블릿에 이미지가 들어갈지 화면에 표시되지 않는다.

## 범위

- 블릿 메뉴에서 한 개 이상의 이미지 파일 선택
- Notes 본문에 한 개 이상의 이미지 파일 드롭
- 이미지 데이터를 포함한 클립보드 붙여넣기
- 드롭 대상 블릿 강조와 실제 첨부 위치의 점선 placeholder 표시
- 다중 이미지의 순서 보존, 사전 검증, 원자적 저장 및 단일 `Undo`
- 기존 이미지 표시, 리사이즈, 내보내기 및 저장소 정리 동작 유지
- 파일 선택 권한 및 관련 회귀 테스트 추가

## 범위 제외

- 이미지 편집, 자르기, 회전, 주석
- 이미지 갤러리 또는 lightbox
- 인터넷 URL의 이미지 다운로드
- 이미지가 아닌 일반 파일 첨부
- 드롭으로 블릿 구조 자체를 이동하는 기능 변경

## 사용자 경험

### 파일 선택

1. 사용자가 블릿 메뉴에서 `Upload image`를 선택한다.
2. 운영체제 파일 선택기가 열리고 여러 이미지 선택을 허용한다.
3. 선택한 이미지를 선택 순서대로 대상 블릿에 추가한다.
4. 취소한 경우 데이터나 오류 메시지를 만들지 않는다.

### 드래그 앤 드롭

1. 사용자가 이미지 파일을 Notes 본문 위로 드래그한다.
2. 포인터 아래의 블릿 또는 현재 확대된 페이지 헤더를 대상 항목으로 계산한다.
3. 대상 항목의 배경과 테두리를 강조하고, 기존 첨부 이미지 다음 위치에 고정 높이의 점선 이미지 placeholder를 표시한다.
4. 다른 항목으로 이동하면 표시도 즉시 이동한다. Notes 대상 밖으로 나가거나 드롭이 끝나면 표시를 제거한다.
5. 드롭하면 모든 이미지 경로를 원래 순서대로 한 번에 import한다.

드롭 대상이 유효하지 않으면 저장하지 않고 미리보기도 표시하지 않는다. 이미지가 아닌 파일만 드롭한 경우 기존 노트 편집 상태를 변경하지 않고 지원 형식 안내를 표시한다.

### 클립보드 붙여넣기

1. 제목, supporting note 또는 페이지 제목을 편집 중이면 그 항목을 대상으로 사용한다.
2. 그 밖에는 현재 선택된 블릿을 대상으로 사용한다.
3. 클립보드에 포함된 모든 이미지 항목을 원래 순서대로 수집한다.
4. 이미지가 하나라도 있으면 기본 붙여넣기를 막고 이미지 일괄 입력을 실행한다.
5. 이미지가 없으면 텍스트 붙여넣기 등 브라우저의 기존 동작을 그대로 유지한다.

## 원자적 다중 저장 정책

- 모든 이미지를 저장 전에 검증한다.
- 지원 형식, 파일 크기, 디코딩 가능 여부, 픽셀 수, 애니메이션 프레임 수, 노드 및 vault 첨부 한도를 전체 묶음에 적용한다.
- 기존 제한인 이미지당 20 MiB, 노드당 128개, vault당 512개를 유지한다.
- 한 번의 입력 작업에서 전달하는 전체 원본 데이터는 최대 64 MiB로 제한하여 IPC 및 메모리 사용량을 제한한다.
- 하나라도 검증에 실패하거나 저장 중 오류가 나면 새 첨부 레코드와 파일을 모두 되돌린다.
- 성공하면 모든 이미지가 입력 순서대로 추가되고 히스토리 항목 하나만 생성된다.
- `Undo` 한 번으로 해당 묶음 전체를 제거하고 `Redo` 한 번으로 전체를 복구한다.

오류 메시지는 실패한 파일명과 이유를 보여준다. 일부 이미지를 자동으로 건너뛰어 부분 성공시키지 않는다.

## 아키텍처

### UI 경계

`NotesAttachmentUiBoundary`가 파일 선택과 네이티브 드롭 이벤트를 앱 UI에서 분리한다.

- 파일 선택 메서드는 단일 경로가 아닌 경로 배열을 반환한다.
- 네이티브 구현은 Tauri webview의 `onDragDropEvent`를 구독한다.
- 물리 좌표를 현재 window scale factor로 논리 좌표로 변환한다.
- 테스트 및 브라우저 실행을 위해 동일한 형태의 주입 가능한 이벤트 경계를 제공한다.
- 구독 해제 함수로 pane unmount 시 listener를 정리한다.

### 드롭 대상 계산과 미리보기

`NotesOutlinePane`이 네이티브 드롭 상태와 대상 노드 ID를 관리한다. `document.elementFromPoint`와 항목의 명시적 data attribute를 이용해 현재 대상을 찾는다.

`OutlineNodeRow`와 `NotesPageHeader`는 다음 표현만 담당한다.

- 활성 드롭 대상 상태
- 대상 항목 강조 스타일
- 기존 첨부 목록 끝에 표시하는 점선 placeholder

placeholder는 레이아웃이 흔들리지 않도록 고정된 최소 높이를 사용하고, 이미지 입력 위치를 텍스트 설명 없이 이미지 아이콘으로 나타낸다.

### 입력 전송

파일 선택과 드롭은 운영체제 경로 배열을 JSON 명령으로 전달한다. 클립보드는 경로가 없으므로 Tauri raw IPC를 사용한다.

- metadata에는 대상 노드, 파일명, MIME 형식, byte 길이와 이미지 순서를 포함한다.
- raw body에는 이미지 byte 배열을 metadata 순서대로 이어 붙인다.
- Rust 명령은 길이 합과 body 크기가 정확히 일치하는지 확인한 뒤 각 이미지를 분리한다.
- base64 이미지 본문과 임시 파일은 사용하지 않는다.

경로 입력과 byte 입력은 Rust 내부에서 공통 `PreparedAttachment` 묶음으로 변환되어 같은 검증 및 저장 경로를 사용한다.

### 저장소 트랜잭션

새 batch repository 연산은 다음 순서로 처리한다.

1. 모든 입력을 읽고 안전한 파일명과 형식을 결정한다.
2. 전체 묶음의 제한과 각 이미지의 유효성을 검사한다.
3. SQLite immediate transaction과 Notes history transaction을 한 번 시작한다.
4. content hash 기반 저장 파일을 준비하고 첨부 레코드를 입력 순서대로 생성한다.
5. workspace와 storage identity를 검증한다.
6. history를 한 번 finalize하고 DB transaction을 commit한다.
7. 실패 시 DB를 rollback하고 이번 작업에서 새로 만든 고아 파일을 reconciliation으로 제거한다.

이미 존재하는 동일 content hash 파일은 중복 제거 규칙을 유지하며, rollback 시 다른 첨부가 참조하는 파일은 삭제하지 않는다.

## 권한

`src-tauri/capabilities/default.json`에 `dialog:allow-open`을 추가한다. 기존 `dialog:allow-save`와 다른 권한은 변경하지 않는다.

## 오류 처리

- 파일 선택 취소: 조용히 종료
- 지원하지 않는 형식: 전체 취소 후 파일별 원인 표시
- 손상되거나 실제 내용과 확장자가 다른 이미지: 전체 취소
- 이미지당 또는 batch 용량 초과: 전체 취소
- 노드 또는 vault 개수 제한 초과: 전체 취소
- raw IPC metadata/body 불일치: 저장 없이 잘못된 요청 오류
- 디스크 또는 DB 오류: transaction rollback, 고아 파일 정리 후 재시도 가능한 오류 표시
- 드롭 listener 초기화 실패: 메뉴 선택과 붙여넣기는 유지하고 드롭 오류만 표시

오류가 발생해도 현재 선택, 커서 위치, 블릿 접기 상태는 변경하지 않는다.

## 테스트

### 프론트엔드

- capability 설정에 `dialog:allow-open`과 `dialog:allow-save`가 모두 존재한다.
- 파일 선택기가 복수 경로를 반환하고 취소는 no-op이다.
- 네이티브 `enter`, `over`, `leave`, `drop` 이벤트가 대상 강조와 placeholder를 올바르게 갱신한다.
- 확대 페이지 헤더와 일반 블릿 모두 드롭 대상이 된다.
- 대상 밖 드롭은 import하지 않는다.
- 여러 경로를 받은 드롭과 파일 선택은 원래 순서를 유지해 batch command를 한 번 호출한다.
- 여러 클립보드 이미지를 순서대로 raw IPC body에 넣는다.
- 이미지가 없는 붙여넣기는 기본 텍스트 붙여넣기를 방해하지 않는다.
- 성공과 실패 후 드롭 미리보기가 항상 제거된다.
- listener가 unmount 시 해제된다.

### Rust 및 저장소

- 여러 경로 및 여러 byte 입력의 순서가 보존된다.
- 하나가 손상되거나 제한을 넘으면 레코드와 파일이 하나도 남지 않는다.
- 저장 중간 실패도 전체 rollback하고 공유 content hash 파일은 보존한다.
- metadata 길이, MIME, body 경계 검증을 우회할 수 없다.
- 성공한 batch는 history 항목 하나를 생성하며 Undo/Redo가 전체 묶음에 적용된다.
- 노드, vault, 이미지당 크기 및 batch 64 MiB 제한을 검증한다.
- 기존 단일 이미지 import, 표시, 리사이즈, export, trash 및 purge 테스트가 유지된다.

### 실제 앱 검증

- macOS Tauri 앱에서 메뉴 파일 선택기가 정상적으로 열리고 복수 선택이 된다.
- Finder에서 여러 이미지를 드래그할 때 대상 강조와 placeholder가 포인터를 따라간다.
- 여러 이미지를 드롭하고 붙여넣은 뒤 표시 순서와 크기 조절을 확인한다.
- 각 입력 묶음에서 `Cmd+Z` 및 `Cmd+Shift+Z`가 전체 이미지를 한 번에 제거하고 복구하는지 확인한다.
- 텍스트 붙여넣기와 기존 블릿 편집 단축키에 회귀가 없는지 확인한다.

## 성공 기준

- `Upload image`가 권한 오류 없이 동작한다.
- 파일 선택, 드롭, 붙여넣기에서 여러 이미지가 모두 입력 순서대로 추가된다.
- 드롭 전에 정확한 대상과 이미지 삽입 위치가 표시된다.
- 다중 입력은 부분 저장 없이 전체 성공 또는 전체 취소된다.
- 한 번의 `Undo`와 `Redo`가 다중 이미지 묶음 전체에 적용된다.
- 기존 Notes 기능과 Yonalist의 다른 기능에 회귀가 없다.
