# Notes Inline Caret Design

## 목적

Notes 본문의 블릿 제목을 마우스로 클릭했을 때 별도의 선택 밑줄을 표시하지 않고, Workflowy처럼 클릭한 글자 위치에 즉시 편집 커서를 배치한다.

Workflowy 공식 편집 설명의 "Click any node to place your cursor and start typing" 동작을 기준으로 삼는다.

## 범위

- 활성 Notes 아웃라인에 표시되는 블릿 제목에 적용한다.
- 제목의 일반 텍스트를 누르면 같은 포인터 위치에 편집 커서를 놓는다.
- 제목 입력창이 포커스를 얻었을 때 표시되는 하단 강조선은 제거한다.
- 블릿 점을 누르는 Zoom 동작은 유지한다.
- 접기/펼치기 화살표와 항목 메뉴 동작은 유지한다.
- 태그를 누르는 필터 동작과 날짜를 누르는 편집 동작은 유지한다.
- 키보드로 제목 표현에 접근해 Enter 또는 Space를 누르는 기존 편집 진입은 유지한다.

## 범위 제외

- 좌측 Notes 페이지 목록의 이름 변경 방식은 수정하지 않는다.
- 페이지 헤더 제목과 supporting note의 클릭 동작은 수정하지 않는다.
- 태그와 날짜 토큰의 클릭을 텍스트 편집으로 바꾸지 않는다.
- `contenteditable` 기반 편집기로 전환하지 않는다.

## 상호작용 설계

1. 사용자가 블릿 제목의 일반 텍스트를 누른다.
2. 표시 전용 텍스트 계층에서 포인터 좌표에 해당하는 UTF-16 텍스트 위치를 계산한다.
3. 현재 마운트되어 있는 제목 `textarea`를 편집 상태로 전환하고 포커스를 이동한다.
4. 계산한 위치에 접힌 선택 영역을 설정하여 커서를 표시한다.
5. 좌표를 텍스트 위치로 변환할 수 없는 경우에는 가장 가까운 안전한 위치로 제한한다. 브라우저 API가 위치를 제공하지 못하면 제목 끝에 커서를 둔다.
6. 포인터 활성화 과정에서는 텍스트 선택이나 포커스 밑줄이 잠깐 나타나지 않아야 한다.

태그와 날짜 토큰은 자체 포인터 이벤트에서 상위 제목 편집 진입을 막으므로 기존 명령을 그대로 수행한다.

## 구현 설계

### `NoteTextField`

- 포인터로 편집을 시작할 때 사용할 선택 위치를 임시 ref에 저장한다.
- `document.caretPositionFromPoint`를 우선 사용하고, WebKit 호환을 위해 `document.caretRangeFromPoint`를 대체 경로로 사용한다.
- 표시 계층의 자식 텍스트 노드를 기준으로 얻은 위치를 전체 원문 UTF-16 오프셋으로 변환한다.
- 편집 상태가 렌더된 후 `focus()`와 `setSelectionRange(offset, offset)`를 같은 layout effect에서 실행한다.
- 이 동작은 명시적인 opt-in 속성으로 제공하여 아웃라인 블릿 제목에만 적용한다.
- 키보드 편집 진입은 기존 호환성을 위해 현재 포커스 정책을 유지한다.

### `OutlineNodeRow`

- 블릿 제목의 `NoteTextField`에 포인터 위치 커서 기능을 활성화한다.
- supporting note에는 활성화하지 않는다.

### 스타일

- `.notes-node-title:focus-visible`의 하단 box-shadow를 제거한다.
- textarea 자체의 기본 outline은 계속 제거하여 입력 중 별도 밑줄이나 테두리가 보이지 않게 한다.
- 블릿, 메뉴, 태그, 날짜 등 명령 컨트롤의 focus-visible 표시는 유지한다.

## 경계 조건

- 한글, 일본어, 이모지처럼 UTF-16 코드 단위와 화면 글리프가 다른 문자열에서도 유효한 선택 위치만 전달한다.
- 여러 줄로 접힌 제목은 실제 클릭한 줄과 글자 위치를 사용한다.
- 빈 제목은 위치 `0`에 커서를 둔다.
- 비활성화 또는 읽기 전용 필드는 포인터 편집에 들어가지 않는다.
- 태그와 날짜 토큰을 누르면 커서가 이동하지 않고 기존 토큰 동작만 수행한다.

## 테스트

### 단위 테스트

- 일반 텍스트 중간을 누르면 계산된 UTF-16 위치에 커서가 놓인다.
- 이모지가 포함된 제목도 유효한 UTF-16 위치를 사용한다.
- 위치 API가 실패하면 제목 끝으로 대체한다.
- 키보드 편집 진입, 태그 클릭, 날짜 클릭, 읽기 전용 동작이 유지된다.
- supporting note에는 새 포인터 커서 정책이 적용되지 않는다.

### 시각 및 통합 검증

- 실제 Tauri 앱에서 블릿 제목을 여러 위치에서 클릭해 커서 위치를 확인한다.
- 클릭 및 편집 상태에서 제목 아래 강조선이 없는지 확인한다.
- 태그, 날짜, 블릿 Zoom, 접기/펼치기, 메뉴 동작을 확인한다.
- 전체 Notes 테스트와 제품 빌드를 실행한다.

## 성공 기준

- 블릿 제목의 일반 텍스트를 한 번 클릭하면 추가 선택 단계 없이 해당 위치에서 바로 입력할 수 있다.
- 클릭 또는 편집 중 제목 아래 별도 강조선이 나타나지 않는다.
- 기존 토큰 및 구조 명령 동작에 회귀가 없다.
