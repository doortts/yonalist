Yonalist 시스템 아키텍처 상세 분석

Yonalist는 로컬 볼트(Vault)와 SQLite 데이터베이스를 기반으로 계층형 아웃라인(Outline) 노트를 관리하는 고성능 로컬 퍼스트(Local-first) 데스크톱 애플리케이션입니다. 헥사고날 아키텍처(Hexagonal Architecture), 가역적 패치(Reversible Patches), HLC(Hybrid Logical Clock) 기반 분산 동기화 및 철저한 경계 검증을 특징으로 합니다.

Rust 1.97+ (2024 Edition) Tauri v2.11 React 19 + TypeScript SQLite 3 (rusqlite / FTS5) Hybrid Logical Clock (HLC)
01

시스템 핵심 철학 및 설계 원칙

로컬 퍼스트 & 데이터 주권 🏠
모든 데이터는 사용자 로컬의 SQLite 파일과 일반 텍스트 Markdown 볼트에 저장됩니다. 원격 서버 의존성 없이 100% 오프라인 작동을 보장하며, 클라우드 중단 시에도 안전합니다.
순수 도메인과 부수효과 격리 🛡️
도메인 규칙(notes-core)은 DB, IPC, React, 플랫폼 API를 일체 참조하지 않는 순수 함수와 데이터 불변성으로 작성됩니다. 모든 명령은 가역적 패치(DomainPatch)로 계획됩니다.
단일 DB 워커 & 무병목 I/O ⚡
SQLite 연결은 단일 전용 백그라운드 스레드(DB Worker)가 독점 소유합니다. UI 스레드와의 경합을 방지하고 mpsc 채널 메시지 전달로 트랜잭션 충돌을 근원 차단합니다.
💡
Strict Architectural Budgeting: 본 프로젝트는 scripts/checkV2Architecture.mjs를 통해 의존성 사이클 금지, 프로덕션 소스 파일 500라인 이하, 테스트 800라인 이하, Crate별 직접 의존성 20개 이하, Tauri IPC 23개 커맨드 완벽 화이트리스트 검증을 CI 단계에서 강제합니다.

04

SQLite 스토리지 엔진 & 스키마 v1

단일 전용 DB 워커 패턴 🧵
SqliteStorage는 자체 전용 백그라운드 OS 스레드를 생성하고, 크로스-스레드 채널(std::sync::mpsc)을 통해 요청을 처리합니다. SQLite 연결(rusqlite::Connection)이 스레드 경계를 절대 넘지 않으므로, 락 경합이나 교착 상태(Deadlock)가 원천 배제됩니다.
컨텐트 주소화 이미지 스토리지 🖼️
이미지 바이너리 바이트는 SQLite DB에 직접 들어가지 않습니다. 대신 SHA-256 해시값(content_hash)으로 애셋 디렉토리에 개별 파일로 저장됩니다. 중복 업로드가 방지되고, DB 파일 크기가 항상 컴팩트하게 유지됩니다.
테이블 명 특징 및 제약 조건 주요 역할 및 컬럼 설명
notes_meta STRICT, singleton = 1 단조 증가(Monotonic) 리비전 번호 저장 (낙관적 락 충돌 감지용)
notes_nodes STRICT, CHECK(kind IN (...)) 노트 트리 구조 (id, parent_id, sort_key, text, note, marker, hlc, path)
notes_images STRICT, FK to notes_nodes 이미지 노드 메타데이터 (content_hash, pixel_width, display_width, mime_type)
notes_tags STRICT, PRIMARY KEY(node_id, token) 트랜잭션 트리거로 파생 추출되는 정규화된 #태그, @멘션 인덱스
notes_dates STRICT, PRIMARY KEY(node_id, date_key) 노트 본문에서 파생 추출되는 ISO 날짜(YYYY-MM-DD) 키
notes_fts VIRTUAL TABLE USING fts5 FTS5 기반 고속 전문 검색 테이블 (Insert/Update/Delete 트리거 자동 동기화)
sync_documents STRICT, root_id PK 볼트 내 Markdown 파일 맵핑, 파일 mtime, 파일 해시, 격리 여부 관리
sync_dirty_nodes STRICT, node_id PK HLC 트리거에 의해 마킹된 디스크 파일 동기화 대기 큐 (Outbox)
sync_conflict_log STRICT, AUTOINCREMENT HLC 타임스탬프 경쟁에서 패배한(Loser) 변경사항의 JSON 스냅샷 보존
05

Markdown 볼트 동기화 & HLC (Hybrid Logical Clock)

Yonalist는 중앙 서버 없이도 여러 기기에서 Markdown 파일을 수정했을 때 발생할 수 있는 충돌을 수학적으로 해결하기 위해 Hybrid Logical Clock (HLC)을 탑재했습니다.

1. 트리거 기반 HLC 자동 타임스탬핑 (Auto-stamping)
사용자가 노트를 작성하거나 수정하면 SQLite 내부의 AFTER UPDATE / AFTER INSERT 트리거가 yona_hlc()를 호출하여 인과적 순서가 보장된 HLC 문자열을 기록하고 sync_dirty_nodes에 변경 플래그를 세웁니다.
2. 비동기 Outbox 내보내기 (Export Pipeline)
SyncRuntime이 디바운스된 큐를 모니터링하여 더티 노드가 속한 문서를 Markdown으로 렌더링하고, 아토믹 파일 쓰기를 통해 볼트 디렉토리에 동기화합니다.
3. 볼트 파일 감시 및 인테이크 (File Watcher & Intake)
외부 에디터(VS Code, Obsidian 등)에 의해 볼트 파일이 수정되면, VaultWatch가 이벤트를 포착하여 파서(notes-sync/parse.rs)로 전달합니다.
4. 비파괴적 LWW 병합 & 격리 (Merger & Quarantine)
수신된 노드의 HLC와 DB의 HLC를 비교하여 최신 노드를 채택(Last-Write-Wins)합니다. 밀려난 변경은 sync_conflict_log에 안전하게 기록되며, 문법 오류가 있는 파일은 sync_quarantine에 보관되어 원본 데이터 유실을 방지합니다.
06

Tauri v2 호스트 & 보안 수명주기

비차단 초고속 부트스트랩 (StartupGate) 🚀
앱 실행 시 WebView 로딩(약 294KB JS 번들)과 SQLite 초기화가 병렬로 진행됩니다. StartupGate를 통해 DB 워커가 최대 80개 노드의 BootSnapshot을 사전 계산하여 첫 화면 렌더링 지연(FCP)을 최소화합니다.
보안 모델 & 정밀 권한 ACL 🔒
엄격한 CSP(Content Security Policy)가 적용되어 임의 스크립트 실행이 차단됩니다. Tauri 커맨드는 main-window.toml에 명시된 23개 핵심 커맨드만 허용되며, 단일 인스턴스 락(Single-Instance Plugin)이 중복 프로세스 실행을 차단합니다.
⚠️
세션 종료 시 정밀 리컨실리에이션 (Close Cleanup): 앱 종료 시(notes_close_session) 진행 중인 트랜잭션 플러시 후 PRAGMA optimize를 수행하며, DB에서 참조가 끊긴 고아 이미지 파일들을 안전하게 정리합니다. (시작 시에는 I/O 부하 방지를 위해 디렉토리 스캔을 수행하지 않음)
07

프론트엔드 상태 관리 & React 19 아키텍처

무거운 외부 상태 관리 라이브러리(Redux, Zustand 등) 대신, Yonalist는 도메인에 완벽히 최적화된 Custom External Store (NotesStore) 패턴을 채택했습니다.

StoreDrafts (300ms Debounce) ✍️
키보드 입력 시 즉각적인 로컬 Paint를 수행하고, 300ms 디바운스, 포커스 이동(Blur), 또는 창 닫기 시에만 IPC 커맨드를 발행하여 타이핑 레이턴시를 0ms에 가깝게 유지합니다.
StoreViewport (80-node Window) 🪟
수만 개의 노드가 있는 대형 문서도 최대 80개의 뷰포트 노드만 메모리에 페이징 로드하여 DOM 노드 과부하를 방지하고 부드러운 스크롤을 보장합니다.
StoreSubscriptions (Fine-grained) 🎯
개별 노드 컴포넌트(useNotesNode)는 자신이 속한 노드의 ID 변경만 구독합니다. 한 줄을 수정해도 전체 트리가 리렌더링되지 않는 고성능 렌더링 트리를 구현했습니다.
인터랙션 히스토리 & Undo/Redo 결합 ↩️

동일한 historyGroup을 가진 연속된 타이핑은 하나의 Undo 단위로 자동 병합(Coalescing)됩니다. 내비게이션 이동 시 "히스토리 펜스(Fence)"가 생성되어 타이핑 그룹이 분리되며, UI의 페인(Pane) 내비게이션 히스토리와 Rust의 데이터 뮤테이션 히스토리가 매끄럽게 결합되어 작동합니다.

08

데이터 변경 및 실행 파이프라인 (Data Mutation Pipeline)

🔄 End-to-End Mutation & Reconciliation Sequence
Step 1: Editor 입력 및 낙관적 UI 반영
사용자가 텍스트 입력 시 StoreDrafts가 즉각 로컬 오버레이에 상태를 반영(Zero Lag Paint). 300ms 후 api.notes_execute() 호출.
Step 2: Tauri IPC 거버넌스 및 세션 권한 검증
DesktopRuntime이 활성 세션을 확인하고 NotesService로 명령 전달. 멱등성 캐시(Idempotency Cache)로 중복 패킷 필터링.
Step 3: notes-core 가역적 패치 계획
순수 함수 NotesTree::plan_command()가 트리 불변식을 검증하고 Forward/Inverse 패치(DomainPatch) 생성.
Step 4: DB Worker 원자적 커밋 & HLC 트리거
SQLite 트랜잭션 내에서 리비전 번호를 확인하고 노드를 업데이트. HLC 트리거가 실행되어 sync_dirty_nodes에 기록 후 MutationReceipt 반환.
Step 5: 프론트엔드 영수증(Receipt) 확정 & 볼트 파일 출력
프론트엔드는 수신된 MutationReceipt로 낙관적 상태를 확정(Confirmed)하고, 백그라운드에서는 SyncRuntime이 Markdown 파일을 안전하게 갱신.

아키텍처 거버넌스 & 자동화된 적합도 함수 (Fitness Functions)

아키텍처가 시간이 지나며 부식되는 것을 방지하기 위해 엄격한 자동화 검증 스크립트가 CI 파이프라인의 필수 게이트로 동작합니다.

체크 항목 📋
  • Crate 의존성 DAG 검증: 상위 Crate로의 역류 및 순환 참조 0건 강제.
  • Tauri 커맨드 화이트리스트: 23개 IPC 커맨드가 main-window.toml 및 build.rs와 1:1 일치하는지 전수 검사.
  • 프론트엔드 모듈 순환 차단: apps/desktop/src 내 순환 import 즉시 빌드 실패.
  • 코드 라인 수 예산 (Budget): 소스 파일 최대 500라인, 테스트 800라인 제한.
